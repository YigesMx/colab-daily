# EmbodiedSkills: A Unified Framework for Orchestrating, Training, and Deploying VLA Agents

**一句话结论**：浙江大学联合云深处科技等机构提出 EmbodiedSkills，把 VLA 动作模型升级为闭环具身智能体：每个技能决策都是"执行提案"，运行时先检查前置条件、后验证执行结果，用固定的可执行技能契约把高层 VLM 规划、有界低层 VLA 执行与事后验证接进同一个 agent loop——任务适配的 π0.5 底层策略在 RoboTwin 2.0 五十任务宏平均 86.20%（参考 82.74%）、LIBERO 四套件平均 97.40%，受控消融显示去掉中间验证掉 38.0 点、去掉语义子任务掉 51.8 点。

## 研究问题与贡献

VLA 模型把观测和指令直接映射为动作，但长程任务需要的不只是动作预测：智能体要在物理状态演化中协调感知、规划、执行、进度验证与恢复。模型生成的技能决策本身并不保证该操作在当前状态下合法，也不保证其结果会被核验。EmbodiedSkills 的核心主张：把每个技能决策当作"执行提案"对待——运行时在执行前检查前置条件、执行后验证产出，让学习到的感知/规划/验证/动作生成可组合而不共享内部表示。

贡献（原文报告）：可执行技能契约（类型化输入输出 schema、前置条件、执行操作、状态更新、失败映射），同时充当组合接口、运行时有效性边界和结构化训练轨迹来源；守护式运行时转换（技能/推进/终止三种控制分别有守卫）；相结构技能空间；组件级监督适配 + 可选闭环适配的 agentic 层训练路径。

## 方法与系统

**Agent 状态与决策**。循环状态 s_t=(z_t, M_t, H_t)：当前相位、可用任务工件集、有序循环轨迹。工件包括观测、感知/接地结果、世界状态、完整任务计划、活动子目标、预检证据、动作块、执行报告、验证报告与恢复上下文，携带来源与新鲜度信息。策略拿到部署一致的紧凑上下文（保留完整计划、活动子目标、工件摘要、近期错误与有界决策历史），从相位相关的动作集中选结构化决策：RunSkill(k,q) / AdvanceStage / FinishRun。

**可执行技能契约**。每个技能 k=(X,Y,pre,exec,post,fail)：模型生成的结果在 schema 与前置条件通过前只是提案；成功输出成为可支撑后续技能的类型化工件，失败保留为下一次决策可用的显式证据。契约同时定义失效边界——观测/子目标/执行结果变化时只刷新依赖它的工件，防止陈旧预测授权新的物理动作。

**守护运行时**。技能提案须同时满足：属于当前相位、在相位技能集中、全部前置条件成立；推进须当前相位产出后继相位所需证据；否则记为 blocked 决策。策略负责"选择有意义的操作"，运行时负责执行安全与状态一致性。

**有界动作执行与验证恢复**。Execute 相位中低层 VLA 把（活动子目标、当前观测、机器人状态、就绪证据）映射为有界动作块 + 执行报告；Verify 相位从执行后观测判断子目标完成；Recover 相位处理失败（重试/换技能/重规划）。六相位（Observe/Plan/Preflight/Execute/Verify/Recover）是语义结构而非刚性单遍程序。

**训练 agentic 层**。组件级监督适配：把规划、相位感知技能选择、事后验证分别用部署一致轨迹训练（高层组件可在冻结低层 VLA 下独立改进）；部署一致样本防止训练-执行不一致；可选闭环适配在有交互反馈时在线改进。

## 实验设置与数据

RoboTwin 2.0：50 个操作任务，每个任务用子任务级演示微调一个 π0.5 策略，全部经同一执行接口接收观测/状态/子目标，报告任务宏平均并与 LingBot-VA 报告的 π0.5 及基准策略结果对比。LIBERO：四套件（Spatial/Object/Goal/Long），对照官方 OpenPI 发布值。RMBench：四个依赖交互记忆的 M(n) 任务对照已发表结果。另有三个受控 AgentLoop 消融（同规划器/底层策略/初始状态/终态评估器，5000 episode）：去掉中间验证（保留预算的固定开环块）、去掉语义子任务（每块只给整任务指令）、每子任务一块（32 步不重试）。

## 结果、限制与结论

**执行性能（论文报告值）**：RoboTwin 2.0 五十任务宏平均 86.20%，对比参考 π0.5 的 82.74%（+3.46 点），最大增益 Hanging Mug +20、Blocks Ranking Size +15、Open Microwave +15；LIBERO 平均 97.40% vs OpenPI 96.85%，四套件全升且 Long 增益最大（92.4→93.6）——执行接口不绑定单一基准或任务分类。RMBench 记忆任务四任务宏平均 12.5%（Cover Blocks 6%、Press Button 0%），论文如实报告该短板并保留原文对照。

**AgentLoop 消融（论文报告值）**：Full 86.20% → 去验证 48.2%（−38.0 点）→ 去语义子任务 34.4%（−51.8 点）→ 每子任务一块 19.5%。解释：语义子任务所需执行预算随初始状态与实际运动变化，固定开环分配无法按观察进度调整块数；只给整任务指令时低层策略每块都要同时推断"当前阶段"和"所需运动"；且很多子任务本身就超过一个有界动作块——三个机制（显式子任务 + 事后验证 + 自适应续块）必须组合。

**限制（论文自述）**：整体性能受两层共同约束；RoboTwin 实例化为逐任务适配的专用策略，维护五十个专家的训练/存储/部署成本高于单一通用策略；守护循环带来额外 VLM 调用与执行后观测的延迟；显式契约不能保证语义上合理的决策就是正确的（错误接地可通过 schema 检查仍把执行带向错误物理状态）；验证在遮挡/视觉歧义/依赖不可见属性时受限；模块化适配在接口边界上的兼容协调与长 episode 误差累积是内禀代价。track 补充：RMBench 12.5% 表明交互记忆是当前执行接口的明确弱项；消融的规划器/评估器固定，未报告延迟开销的具体数字（原文未报告）。
