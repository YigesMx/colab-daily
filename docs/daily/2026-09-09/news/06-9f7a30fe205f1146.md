## 事件概述

华为诺亚方舟实验室前主任、盘古大模型负责人王云鹤创办的基元律动（TokenRhythm）发布了公司首个自研模型 NeoHorse-1，包含 4B 与 9B 两个规模，定位为"Agent 原生"模型：后训练数据的核心来源是其多模型路由调度系统（Routing Harness）在真实任务执行中沉淀的轨迹信号，而非仅靠人工整理的问答语料。据量子位报道，该模型由无问芯穹提供算力支持与 Infra 优化，清华大学、北京大学团队参与算法与训练方法研究。模型以 Apache 2.0 协议开源，同步放出了技术报告（arXiv:2609.08183）、GitHub 仓库、Hugging Face 与 ModelScope 权重及 GGUF 量化版本。

## 已确认事实与证据

以下事实来自官方 GitHub 仓库与 README、arXiv 技术报告、Hugging Face 集合页及量子位报道，全部证据已留存：

- 模型定位（官方 README 原文）：NeoHorse-1 是"走向递归自我改进（RSI）之路上的一个初始原型"，是"从 Qwen3.5 后训练而来、面向文本 Agent Harness、工具使用、编程与指令遵循的因果语言模型家族"。
- 数据闭环：官方技术报告描述，路由系统为每一轮交互记录预测的能力需求、选择的服务层级与后续交互，这些记录被转换为保留交错推理、工具调用与 Harness 上下文的训练样本；样本经结构校验、六维语义评估与子场景级标注后才准入。量子位报道称六维评估包括是否完成用户目标、是否遵守指令、工具使用是否合理、结论是否有证据支撑、错误后能否恢复、是否在合适时机终止任务。
- 训练方法：路由信号把监督微调组织为三阶段课程（先低能力需求任务、后复杂轨迹）；并使用路由引导的在线策略蒸馏（教师针对学生当前分布下的实际步骤给指导）；最后由"能力引导分配"把评测反馈转化为下一轮训练配比。
- 评测结果（技术报告摘要原文）：在覆盖 Harness Agent、工具使用、编程与指令遵循的十项基准上，后训练把 4B 模型宏平均分从 58.94 提升至 64.87，把 9B 模型从 65.60 提升至 69.04，"显著缩小了后训练 4B 与 9B 基础模型之间的总体差距"。量子位报道称 4B 版在所有可对比基准上均超越其基础模型 Qwen3.5-4B，达到同规模领先水平。
- 产品矩阵背景（量子位报道）：基元律动旗下已有开源项目 OpenSquilla（统一接口下多模型细粒度路由与协作）、TokenRhythm API（多模型统一调用接口）与企业部署服务；NeoHorse 验证的是"Harness 执行经验可转化为模型能力"这一环。

## 影响与后续观察

NeoHorse 的辨识度在于它把"用模型的平台"积累的横向执行数据（哪个模型在哪一步失败、哪条修复路径通过环境验证）变成训练资产，这为 API 聚合与模型中间层公司提供了一条差异化的护城河叙事：路由数据既是调度决策的依据，也是下一代模型的课程。若该闭环持续成立，"Data-RSI（执行数据自我供给）+ Model-RSI（按能力短板更新模型）"的工程化 RSF 路线将首次获得开源可复现的样本。

需要观察的要点：其一，技术报告自己承认目前只验证了单轮"执行-评估-选择-更新"闭环，信号与奖励设计仍由人类完成，多代迭代后能否持续增益未知，不宜将其等同于完整 RSI；其二，4B 达到/略超 9B 基础模型的结论依赖其自选的十项基准与宏平均口径，独立评测（尤其与 DeepSeek、Qwen、MiniMax 同规模模型的横向对比）尚缺；其三，训练数据来自自家路由日志，其中用户任务数据的使用边界与脱敏策略未在公开材料中详述；其四，当模型厂商自身向 Agent 基础设施垂直整合（DeepSeek、Qwen、MiniMax 均在延伸 Harness 与 Agent 产品）时，中间层公司的生存空间取决于模型间能力差异是否持续存在，这一结构性风险无法靠单一模型发布消除。
