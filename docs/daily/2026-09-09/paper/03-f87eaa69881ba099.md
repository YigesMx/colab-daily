大语言模型的成功建立在下一 token 预测之上，但自回归结构决定了生成必须逐 token 串行，推理慢且强化学习后训练的 rollout 生成成为瓶颈。阿布扎比科技创新研究院基础模型研究所（Institute of Foundation Models）联合伊利诺伊大学厄巴纳-香槟分校、康奈尔科技校区、哈佛大学与 Cerebras Systems 发布的这项工作，提出了"扩散增强 LLM"（diffusion-augmented LLM）：在同一架构内定义自回归分布，再用扩散权重从这个分布中并行抽出多个 token。由此得到的模型系列 Uno 不需要独立草稿模型，与常规扩散语言模型不同，它不牺牲底层自回归模型的质量，在所有评测批次大小上都超过主流投机解码方法，最高带来 3 倍加速。

## 研究问题与贡献

论文从两个角度论证加速的必要性：语言本身包含可预测的搭配与程式化序列，本可以成块生成；解码在长上下文下是访存受限的，逐 token 生成无法摊销权重与 KV 状态的搬运。现有方案各有缺陷——投机解码依赖一个对齐良好且高效的独立草稿模型；离散扩散语言模型（d-LLM）虽原生支持并行生成，但相对自回归模型存在质量-速度折衷，且其加速在大批次下消失，而现代智能体负载恰恰以并发请求为主，批次为一的延迟只代表很窄的工况。

Uno 的四项贡献：一是提出把决定响应质量的自回归权重与优化生成速度的轻量扩散权重解耦的框架及配套训练管线；二是提出 Ψ-Spec 采样器家族，支持经自回归验证的无损加速，以及固定上下文长度下的推理时扩展；三是展示既能从零训练、也能给现有开放权重自回归 LLM 增配扩散权重；四是证明在基础模型支持的最大批次下仍保有最高约 2 倍加速，同时加速推理与端到端 RL 训练。

## 方法与系统

架构上每层包含两套权重：θ_AR 按标准流程（预训练、SFT、RL 后训练）训练的自回归权重，决定质量；θ_Δ 是挂在每个权重矩阵上的 rank-128 LoRA 适配器（LoRA-α=256），只用于并行起草。草稿路径用 θ_AR+θ_Δ，验证路径只用 θ_AR，两者通过共享底座参数紧密耦合——这既保留了投机解码的无损失真验证，又像自投机解码一样免去独立草稿模型，且草稿与验证共享同一份 KV 缓存，峰值显存更低。模型保留 NTP 参数化（每个位置预测下一个干净 token），与常规扩散语言模型"预测同位置 token"的参数化不同。

训练核心是扩散蒸馏阶段：冻结 θ_AR，只训 θ_Δ，目标是对齐单步扩散分布与自回归教师分布。作者把离散一致性蒸馏（DCD）改造成一步形式——从完全腐蚀的输入直接映射到干净序列，免去在 LLM 规模下构造和存储中间 PF-ODE 状态的巨大开销；并按块进行：把序列切成大小为 B 的块，学生（带适配器）在腐蚀块上的预测对齐教师在干净块上的预测，通过门控 LoRA 在一次前向中同时产生教师与学生 logits（干净位置禁用适配器，腐蚀位置启用）。目标函数是块级 KL 蒸馏损失与块级总变差（TV）损失的加权和；TV 项直接优化投机解码的最长接受前缀期望长度。作者发现先 α=β=1 再切到 α=0、β=1（只训 TV）收敛更快，消融显示只训 TV 的 TPF 最高。

推理用 Ψ-Spec：先从先验采样 B-1 个随机 token 追加到当前序列，一步去噪得到候选分布，第一个 token 永远由纯自回归权重生成故必然被接受，其余 token 构成候选集，用标准投机解码的拒绝校正保留最长有效前缀，多候选时用树注意力并发验证——输出分布与基础自回归模型完全一致，即无损。每个迭代两次前向（起草一次、验证一次），故 TPF 上界为 (B+1)/2。论文还指出一个额外推理时扩展轴：允许去噪步数 T 超过起草 token 数 B，固定上下文长度下增加算力可能提升质量，系统探索留给未来工作。

## 实验设置与数据

评测分两条线。第一条从零训练 8B 稠密模型（36 层、隐藏 4096、250k 词表、配置上下文 524k）：自回归权重用约 23T token 分阶段上下文扩展训练（8K 上 21.9T，32K 上 1.1T，128K 上 0.5T，512K 上 0.3T）；扩散权重只用 7B token（SFT 分布采样，块大小课程 2 到 8，上下文 16k 到 64k），约 60 小时于 8 节点 8 卡 H200。基线为开源 d-LLM Nemotron-Labs-Diffusion-14B、DiffusionGemma-26B-A4B 与闭源 Mercury 2，覆盖 τ³/τ² 工具使用、Terminal-Bench、SWE-bench Verified、长上下文推理 AA-LCR 及数学、代码、知识基准；吞吐统一用 1K 输入/8K 输出的"1K/8K 吞吐测试"在单张 H200 上测系统级（最大批次）与单请求（批次一）两种口径。第二条线给开放权重 Qwen3-8B 增配 0.35B LoRA 参数的扩散适配器：仅在开源 OpenThoughts3-1.2M 上训 14.7B token（与基座训练分布不同），约 32 小时于 4 节点 8 卡 H200；基线为同为 Qwen3 设计的 EAGLE-3（0.40B 自回归草稿）与 DFlash（1.05B 扩散草稿），以及多个有损扩散方法。

## 结果、限制与结论

论文报告：从零训练的 Uno 8B 与基础自回归模型质量相当，批次一时约 2.2 倍加速，基础模型最大批次 64 下仍 1.5 倍；对所有开放 d-LLM 在全部基准上占优——τ² Telecom 90.1 对 DiffusionGemma 68.1、SWE-bench Verified 68.4 对 18.7、AA-LCR 68.0 对 19.7；对比闭源 Mercury 2，8B 的 Uno 在全部智能体工具使用、智能体编码与长上下文推理基准上胜出（如 Terminal-Bench 39.6 对 27），仅在科学知识类的 AA-Omniscience 落后（14.3 对 20），且最大系统吞吐约为 Mercury 2 报告值的 4.6 倍（Uno 运行在更慢的 H200/Hopper 上、bfloat16 精度）。给 Qwen3-8B 增配的 UnoQwen：最大批次下系统吞吐超 5,700 token/s（批次基座 1.6 倍加速），批次一用树采样 (B,K,V)=(16,32,32) 达 2.5 倍加速，在所有批次上 Pareto 支配 EAGLE-3 与 DFlash，同时额外参数更少、共享 KV 缓存峰值显存更低；接受长度上如 MATH500 系统 4.11 对 EAGLE-3 的 2.14。RL 加速方面，在 SFT 检查点上训练的扩散适配器在 DAPO 后训练（四专家：数学、代码、工具使用、网络搜索）期间冻结并加速 rollout，带来最高 40% 的端到端训练加速（数学与代码专家最明显，工具调用主导的专家收益小）；RL 后用 ISO-Merger 合并四专家后适配器 TPF 仅标称下降约 6%。消融确认：只训 TV 损失 TPF 2.39 优于两者混合的 2.23；块大小课程与全层分布适配器均优于替代方案。

需要保留的判断：Uno 的"无损"指分布保持，与草稿接受长度和采样配置相关，其吞吐优势的口径是 1K/8K 固定输入输出测试而非任意负载；与 Mercury 2 的比较受闭源模型的量化与硬件差异影响（作者自己也注明）；智能体专家 RL 加速的详细结果论文承诺在下一版给出，目前证据有限；推理时扩展能否超过自回归质量仍是开放问题，作者明确留给未来工作。总体而言，这篇论文的实用价值在于一条几乎不改变现有训练管线的加速路径——对已有开放权重模型补一小套 LoRA（相对基座不到 5% 参数、7B 到 15B token 的蒸馏数据），即可获得各批次下稳定的无损加速与 RL rollout 提速；代码与检查点已开放。
