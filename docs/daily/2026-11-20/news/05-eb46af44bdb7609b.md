## 事件概述

2026年11月18日，组织 RadixArk 在 Hugging Face 官方博客发布其首个模型 DaisyRose-27B，并以 Apache 2.0 许可开源全部三个精度版本（BF16、FP8、NVFP4）。该模型基于 Qwen3.8-27B 构建，使用其开源强化学习框架 Miles 训练，主打"后训练效率前沿"：仅用 1,200 个精选长时程智能体任务、144 张 H200 GPU、18 天完成训练，即把 Terminal-Bench 4.1 的 pass@1 从基座的 5.6% 提升到 12.0%。官方同时披露了训练后端与沙箱基础设施的工程细节，是一篇信息密度较高的开源技术发布。

## 已确认事实与证据

以下事实均来自 RadixArk 在 Hugging Face 官方博客的发布文章与官方模型页（本次已抓取两个页面存证）：

- 模型与许可（官方宣布）：DaisyRose-27B 是 RadixArk 的首个模型，基于 Qwen3.8-27B，采用强化学习训练；保留基座的架构、分词器、对话模板、图像理解能力与 256K token 上下文窗口；检查点以 Apache 2.0 开源（BF16、FP8、NVFP4），模型页为 RadixArk/DaisyRose-27B。
- 训练设置（官方宣布）：面向长时程智能体任务，会话最长 100 万 token；最终训练集仅 1,200 个精选任务（与 Eigent AI 合作构建数千候选后筛得）；训练历时 18 天、使用 144 张 H200（共约 63,000 GPU 时）。
- 公布的基准结果（官方自报）：Terminal-Bench 4.1 pass@1 从 Qwen3.8-27B 的 5.6 升至 12.0；Terminal-Bench 2.1 从 73.0 到 75.5；DeepSWE v1.1 从 42.2 到 46.2；SWE Bench Pro v2 从 91.3 到 94.7；HLE（纯文本）从 33.9 到 34.3；IFBench 从 79.5 到 82.4；GPQA Diamond 从 89.2 到 90.7；数值取 BF16 与 FP8 中较高者。
- 任务设计三原则（官方描述）：每个任务针对基座的真实错误设计；任务需要多步相互依赖（沙箱内最长 1.5 小时、超过 100 次工具调用、超过 256K 输出 token）；任务必须奖励真正解决问题并经人工审核。
- 训练后端（官方宣布）：Miles 全异步模式，128 张 H200 跑智能体推理、16 张跑训练器，每步更新即时下发；内部后端 MFU 达 37%，官方称开源 Megatron 训练器在可比运行中为 16%，同等训练可省 57% GPU 时间；端到端吞吐约 16,800 token/s 对开源训练器约 8,300 token/s；在 MoE 模型上收益更大（Qwen3.6-35B-A3B 为 6.2 倍，约 3000 亿参数的 GLM-5.3-Flash 超过 10 倍）。
- 沙箱服务（官方宣布）：基于开源项目 AgentENV 构建，9 月中至 11 月中为本项目运行约 94.4 万个沙箱、峰值并发 1,566 个；沙箱创建成功率全程 99%、10 月下旬后超过 99.95%；官方称云成本比主流沙箱服务商低约 80%。
- 推荐部署（官方宣布）：推荐 SGLang 服务与 DSpark 投机解码，模型默认先输出思维链（reasoning_content）再给最终答案。
- 未知与官方未披露：RadixArk 的公司背景与团队构成、Miles 框架仓库地址、上述基准的完整评测配置与第三方复现结果在发布中未提供；所有性能数字均为发布方自报。

## 影响与后续观察

DaisyRose-27B 的意义在于示范了一条"少而精的任务数据 + 高效率异步 RL 后端"的可行后训练路线：1,200 个任务、18 天、144 卡就实现了 Terminal-Bench 4.1 翻倍的成绩，若其 57% 训练成本节省与万级 token/s 的吞吐数据可被复现，将显著降低中小团队做智能体后训练的门槛，也对"后训练必须堆海量数据"的默认假设构成反例。Apache 2.0 的三精度开源（含 FP8/NVFP4）方便了实际部署，与 Qwen 生态的兼容降低了迁移成本。后续可关注：社区在模型页 Community 标签下发布的独立复现结果、Miles 与 AgentENV 的开源进展、DaisyRose 是否成为 RadixArk 后续系列模型的基线，以及该模型在真实工程任务（而非自报基准）中的表现。
