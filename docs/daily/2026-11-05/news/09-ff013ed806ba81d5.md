## 事件概述

艾伦人工智能研究院（Ai2）于11月3日在Hugging Face官方博客发布StateBench，一个测试语言模型“长文档状态追踪”能力的基准：模型需要在长输入中持续记住实体信息的演变，例如代码里变量被反复赋值、小说里人物移动物品改变持有关系等。与既有只测最难情形的状态追踪测试不同，StateBench把问题按复杂度分为四级，用于比较Transformer、循环与混合架构在不同难度状态追踪上的差异。基准配套的技术报告（arXiv:2611.03094）、数据集（Hugging Face allenai/state-bench，68,000行）与代码（GitHub allenai/state-bench）已同步公开。

## 已确认事实与证据

以下事实均已在Ai2官方博客页、论文页与数据集页直接核验：

- 四级难度按“变量赋值类型”直观理解：R-trivial（不可变赋值，如let x = 4，只需取初始值）、aperiodic（按值重赋值，取最新值即可，如恒温器）、soluble（自引用更新，如x = x + 5，需逐步累积，如游戏比分）、general finite（按引用赋值，如x = y或交换变量，对应五个杯子交换的S₅类问题）。分级依据Krohn–Rhodes理论；同一变量赋值序列可派生四个仅操作类型不同的可比问题。
- 预训练模型实验：包括两个70亿参数模型Olmo 3（纯Transformer）与Olmo Hybrid（加入Gated DeltaNet层）及275M、2.7B小模型，全部使用相同预训练数据、训练时上下文均不超过64,000词元。结果：几乎所有模型在R-trivial上表现良好，在aperiodic上随输入变长准确性下降，在general finite上接近随机。题目形式影响显著——275M混合/GDN模型在RULER式R-trivial问题上接近满分，但同一问题改写为表格编辑形式就接近随机，这是StateBench用多种形式测同一问题的原因。
- 前沿模型实验：Gemini 3.8 Flash、Claude Opus 5.5、GPT-6 Sol与GPT-6 Luna四个模型在R-trivial与aperiodic上表现良好，但在soluble与general finite上随输入增长准确率骤降，最长的general finite问题上降到13%或更低。作者认为一个可能因素是敏感度：更难的级别上更多步骤会影响最终答案，漏掉一次更新即出错。
- 直接训练实验：从零训练多个275M模型（两种Transformer、两种混合、两种不同记忆更新约束的Gated DeltaNet变体），训练序列最长256次赋值、测试最长64,000次（训练长度的250倍）。Gated DeltaNet与混合模型在R-trivial、aperiodic、soluble上几乎完美泛化到数万次赋值；Transformer学会了较易级别但长序列上退化，且始终学不会general finite。记忆更新更灵活的GDN变体在最难级别泛化最远，约达训练所见最长序列的10倍长度。
- 新的理论结果：作者证明采用较受限记忆更新（非负特征值）的Gated DeltaNet在论文的定点算术设定下可解全部aperiodic任务与部分周期任务（如判断重复输入出现奇偶次数），其在层级中的确切位置仍开放。
- 发布物料：技术报告页（allenai.org/papers/statebench，对应arXiv:2611.03094 “A Fine-Grained Hierarchy and Benchmark for State Tracking in Language Models”）；数据集allenai/state-bench共68,000行、约1.05GB、18个子集；代码仓库allenai/state-bench。博客作者署名为Kyle Wiggers（Ai2Comms）。

## 影响与后续观察

StateBench的价值在于把“状态追踪”从最难情形的粗粒度判断细化为可分级、可跨架构比较的测量：它为当前大量涌现的循环/混合架构（Gated DeltaNet、 hybrids等）提供了理论动机明确的能力地图，也直接揭示了前沿闭源模型在长链条状态更新上的系统性短板——即便上下文窗口足够，追踪大量赋值链仍会在数万步长度上崩塌。对长文档处理、代码理解、Agent多轮任务记忆等应用，这是比“长上下文检索”更贴近执行层面的能力指标。

后续可关注：社区在各模型上的复测结果与排行榜化；作者指出的开放问题（数值精度与注意力层组合对GDN能力的影响、实体动态加入的设定）；以及以此为指南设计的新架构与针对性训练数据。
