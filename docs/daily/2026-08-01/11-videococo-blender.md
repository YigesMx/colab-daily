## 核心内容

VideoCoCo 处理的是文本生成视频中一个经常被画面质量掩盖的问题：模型能生成看似合理的帧，却未必正确展开升华、碰撞、浮力等过程。论文不让生成模型仅凭压缩的文本提示隐式猜测完整动力学，而是把流程拆为两个引擎。代码代理先把提示写成自包含的 Blender Python 程序，明确场景、物体属性与时间演化；隔离的 Blender 运行时再执行程序，得到确定、逐帧稠密但采用白模材质的时空草稿。这个中间表示既可运行、可检查，也能在渲染错误时提供诊断信号。

第二个生成式视频引擎只负责视觉实现。指令代理同时读取原提示与模拟草稿，生成侧重主体、材质、光照和镜头风格的编辑指令，而不重新定义草稿中的运动。编辑器以草稿固定“发生什么及何时发生”，以编辑指令规定“看起来怎样”，把原本耦合的过程推理和写实生成拆开。推理时用户仍只输入文本，代码、草稿、编辑指令和最终视频均由系统自动产生。

## 关键技术与数据

训练数据 VideoCoCo-3K 包含 3,000 个“模拟草稿、编辑指令、写实目标”三元组。草稿由 Blender 程序渲染，目标视频由 Seedance 2.0 教师编辑器生成；评测提示及其近重复项被排除。视频编辑器从 OmniWeaving 初始化，以草稿和指令为条件、目标视频 latent 为监督，采用标准条件扩散去噪目标。论文比较了不调参、全量微调和 LoRA 三种适配方式。

评测使用两个物理导向基准。PhyGenBench 覆盖力学、光学、热学和材料动力学，以 GPT-4o 按官方协议评判物理一致性；VBench-2.0 使用力学、热学和材料三个维度。对比对象既包括 Pika、Gen-3、Kling、Sora 等 API 系统，也包括 CogVideoX、Wan2.2、Cosmos-Predict2.5、LTX-Video 等开放权重系统，并单列 OmniWeaving 基座以隔离增益来源。原文未提供代码代理具体基座、训练算力或 VideoCoCo-3K 的完整来源分布，不能据此判断成本和数据覆盖面。

## 结果与结论

作者报告，VideoCoCo 将 OmniWeaving 在 PhyGenBench 的平均分从 0.475 提高到 0.558，超过表中最强开放基线 Wan2.2-TI2V-5B 的 0.544；材料和热学相对基座分别增加 0.133 和 0.078。VBench-2.0 平均分从 52.18% 提高到 77.88%，其中力学 92.31%、热学 72.92%，材料 68.42%。在固定模拟草稿的消融中，不调参版本已经达到 0.506，说明可执行草稿本身带来部分增益；全量微调为 0.535，LoRA 最佳为 0.558。

这些结果支持“先显式实例化过程、再做视觉写实化”的分工，但证据仍主要来自自动指标和作者选择的物理基准。模拟器能否表达目标过程、代码代理生成程序的正确率，以及教师生成目标可能带来的偏差，原文没有给出系统性失败率。因此更稳妥的结论是：在给定评测和实现下，可执行时空草稿显著改善了物理一致性，而不是已经解决任意开放世界物理视频生成。
