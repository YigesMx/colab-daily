# Anthropic 改写 Messages API「思考块」规则：上下文一致性验证切断蒸馏路径

## 事件概述

Anthropic 在 9 月 2 日随 Claude Fable 5.1 更新了 Messages API 对「思考块」（thinking block）的处理规则，官方支持文档给出「保留思考」机制与上下文一致性验证的完整说明。新规针对通过篡改上下文套取模型底层推理过程的蒸馏行为，被视为对「API 套壳 + 蒸馏」路径的系统性封堵；新智元 9 月 6 日以《大模型蒸馏时代结束！》为题报道。

## 已确认事实与证据

- 规则内容（官方支持文档）：API 严格验证客户端回传的思考块是否与当初产生它的系统提示、工具与历史消息完全一致；发现任何修改即匹配失败并直接返回错误、拒绝服务。
- 逃生通道：确需修改上下文的合法开发者（如上下文压缩）可选择「非严格模式」——请求照常通过，但系统会静默删除请求中受影响的思考块，模型在看不到此前推理过程的情况下作答。
- 生效范围（官方文件）：率先适用于 2026 年 8 月 31 日 12:00 UTC 之后创建的新 API 账户；现有 API 账户在 Fable 5.1 上暂不受影响；网页端 Claude.ai、Claude Code、Claude Cowork 等消费端用户不受影响。官方同时明确「保留思考」机制将在未来模型版本中适用于所有账户。
- 动机（新智元报道转述 Anthropic 口径）：过去一年安全团队观测到工业级蒸馏滥用——数千虚假账户用自动化脚本，通过「上下文注入」与「对话重写」诱导模型吐出本已加密的思考块；被蒸馏的「小模型」继承高阶推理能力却不继承安全护栏，形成「能力与安全脱钩」风险。
- 附带效应（报道口径）：强制上下文一致性创造了高提示缓存命中率的条件，官方称响应延迟与调用成本将显著下降；该收益为报道转述，当前官方文档未给出量化数字。

## 影响与后续观察

- 依赖「对话中途重写早期轮次」（上下文压缩、中途注入系统提醒）的 API 集成需要改造：或保持逐字一致，或接受非严格模式下思考块被删除的行为差异。
- 对蒸馏生态：以 API 推理数据训练小模型的灰色路径被收紧，「小参数锤爆大模型」叙事的供给端收缩；合规数据合作与自有推理能力的相对价值上升。
- 待观察：全账户强制时间表；非严格模式下多轮任务的性能回归幅度；其他厂商是否跟进同类一致性验证；对长上下文 agent 框架（普遍重写历史）的连锁影响。
