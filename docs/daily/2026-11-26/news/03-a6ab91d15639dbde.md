## 事件概述

Anthropic 于 2026 年 11 月 25 日在官方 research 板块发布工程文章 Migrating our Messages API to Rust，完整复盘了把 Messages API 从 Python 迁移到 Rust 的过程与教训。Messages API 是客户以及 Anthropic 自家应用（Claude Code、Cowork）访问 Claude 的主要通道，自 2024 年初到 2026 年秋，其 API 流量增长约 1800 倍。迁移后的 Rust 版本每请求 CPU 使用降低约 70%、中位首 token 时间缩短约 20%，且全程未让服务下线、也未冻结功能开发。文章的核心论点是：当编写代码不再是瓶颈，验证就成为新的瓶颈——团队把生产系统本身变成了验证器，并让 Claude 智能体团队在多级验证回路中自主完成差异修复。

## 已确认事实与证据

以下事实由 Anthropic 官方文章直接确认：

- 迁移动机与渐进尝试:2023 年上线的 Python 版 Messages API 逐步承担请求校验、提示构建、分词、安全分类、输出分流(文本、思考与工具调用)及用量统计等职责,Python 在每一步对象创建、内存回收与任务交接中都引入开销,流量最终远超初始设计。团队先只把解析模型输出的部分改写为 Rust 并从 Python 调用,使 API 的 CPU 使用降低约 8% 到 10%,但每个回复令牌要在 Python 与 Rust 之间往返三次,新增开销使收益不再值得复杂度。2024 年曾有工程师以“我们不会用 Go 或 Rust 重写 API”暂缓争论，而到 2026 年 5 月，Claude 已编写 Anthropic 合并代码的 80% 以上，全量迁移的可行性显著提高；Claude 用大约一周写出了新 API 核心请求路径的首版代码。
- 验证的三大难点：生产 API 在迁移期间持续演进（"正确"是移动靶）；Claude 对同一请求会非确定性地给出不同回复（两次输出不同不代表有缺陷）；团队不能读取客户请求与回复内容，因此难以直接看到两个版本的分歧点。
- 测试的局限：约 700 个集成测试与 Python 实现耦合（被移植后可能出现"通过"不代表正确的情况，审计移植后的测试时发现了 100 多处被弱化的断言）；且几十项功能与配置组合远超可穷举范围（仅 20 个布尔选项就超过一百万种组合）。
- 影子流量比对：模型只运行一次，模型输出被重放给 Rust，两个版本在每个阶段前后逐步精确比对；以"检查点"定位差异首次出现的服务步骤与提示片段，再以"指纹"（差异在提示中的起点、两侧长度差等形状信息，不含任何文本）区分并聚类缺陷。2026 年 4 月时，Rust API 约 98% 的测试通过，但在生产流量上只有约四分之一的输入完全匹配，缺口主要来自测试未覆盖的生产场景（例如 Python 写 JSON 工具调用时会把 emoji 等字符转义为文本码，而 Rust 原样写出）与生产流量对高频缺陷的加权放大。
- 三层验证回路：内环让每个智能体在带两套代码库的云沙箱中自拟请求或模型回复来复现指纹差异，秒级获得验证信号，修复后补充一个旧码失败、新码通过的测试；外环把通过评审的修复部署到预发环境，在影子流量上检验该缺陷指纹是否消失，不消失则退回内环；记忆环把工程师评审中的纠正沉淀为规则、lint 与测试（例如"精确移植 Python 行为"的规则帮助找出另外七处依赖臆测的移植，另一位智能体还整理了约 60 条评审意见并归纳出写入 CLAUDE.md 的规则）。每 10 到 30 分钟运行一次的脚本把海量差异记录按字段聚类，只在出现新类型时唤醒协调智能体，并在共享 Slack 频道为每个缺陷开线程供工程师跟进与纠偏。
- 人类审核的位置：智能体的修复必须经过拉取请求评审才能进入外环；文章给出了一个典型例子——某智能体为了让提示匹配，提议把 web search 工具描述硬拷贝进 Rust 可读的文件，本地验证通过，但被工程师否决，因为上线前 Rust 仍需调用提供工具描述的内部服务，该变通终将被丢弃。验证器能判断输出是否匹配，却不能判断修复是否值得发布。
- 最终结果：Rust 版 Messages API 每请求 CPU 使用降低约 70%、中位首 token 时间缩短约 20%，公开流量于 2026 年 9 月切换到 Rust；作者为 Lance Martin、Jake Eaton、Arvin Aminpour、Emma Webb、Bharat Mediratta 与 Ravi Trivedi（编辑指导 Caitlin Love）。

## 影响与后续观察

- 方法论上，文章提出"验证是新的瓶颈"：只要能定义可靠的正确性判据（数学用证明助手、软件用测试或形式化验证，必要时用生产系统本身），就能安全提高 Claude 承接大型迁移等任务的雄心；对其他团队的直接参考是三层回路设计与"人的判断只放进什么算正确"的原则。
- 工程细节的启发：差异指纹（不含文本的形状信息）兼顾了隐私与可诊断性；沙箱内环让错误猜测只损失几秒且不影响用户；记忆环把纠正固化为规则与检查，避免人类重复纠错。
- 官方也明确提醒边界：内环模拟生产快但不完美，沙箱通过不代表生产无差异；验证器无法判断修复的工程质量，人工评审仍是必要闸口。
- 后续观察点：该模式向其他大型生产系统迁移的可推广性；防止 Rust 与 Python 双轨漂移的合并检查（改 Python 必须同步改 Rust 或申请豁免）等机制能否长期维持；以及 Claude 编写代码占比继续上升后，验证回路的形态会如何演进。
