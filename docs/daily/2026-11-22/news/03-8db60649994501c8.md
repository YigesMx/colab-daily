## 事件概述

11 月 12 日，卡内基梅隆大学、NVIDIA 等机构的研究者提交了预印本《Singularity-Bench: Can Agents Build Agents?》（奇点基准测试：智能体能构建智能体吗？）。据新智元报道，在其中的推理引擎考题中，Claude Opus 5.5 在给定基础服务器代码、4 张 GB300 显卡和 12 小时限时、禁网的环境下，用 Claude Code 写出一套推理引擎，在真实编程会话回放测试里把 P90 首 token 延迟从成熟引擎 SGLang 的约 12 秒压缩到 0.48 秒。整套测试显示，智能体已在 AI 研发流程的多项工程任务上超过人类基线方案。

该基准共设六道闭卷考题，覆盖训练与基建两大类；由 7 个主流模型与 Claude Code、Codex 两套运行框架组合出的 11 支 AI 队伍参赛。最终 Claude Opus 5.5 搭配 Claude Code 以「五胜一平」成为唯一总分超过人类基线的组合。研究者同时强调，这些题目仍由人类划定范围，尚不能视为递归自我改进（RSI）已经实现。

## 已确认事实与证据

据论文与报道，推理引擎一题的对比条件为：两套引擎各用 4 张 GB300 运行同一个模型，回放同一批 16 路并发的真实编程会话，单次输入中位数约 8.9 万 token。结果 Claude 所写引擎的 P90 首 token 延迟为 0.478 秒，SGLang（v0.5.20）为 12.029 秒；两者缓存命中率均在 96% 左右，生成速度接近（每秒 124.2 对 125.0 个 token，中位数）。报道归因的两项设计是：同段前文的 KV 记录成对缓存复用，以及「剩余计算量少的请求优先」的排队策略，辅以投机解码与 GPU 操作合并，使每 GPU 每秒多处理 19% 的未缓存 token；相同回放时限内完成 983 个请求对 705 个，折算每 GPU 小时产出 11.52 美元对 8.18 美元。

其余各题结果包括：预训练题上 Claude 先用 44 分钟测显卡再定模型规模，以约一半计算量取得 12.77 困惑度，优于人类基线 OLMo 2 1B 搭配 Megatron-LM 的 14.22；中期训练挑数据使下游平均准确率从 17.5% 提高到 31.9%；智能体运行框架题把下游平均分从 0.438 提高到 0.468（人类对照即原版 Claude Code）；集群调度题以 0.510 分超过 NVIDIA Dynamo 搭配 KAI Scheduler 的 0.460 分；后训练题以 53.3% 对 53.9% 的解题率判为平手。等权汇总后 Opus 5.5 搭配 Claude Code 得 1.252 分（人类基线计 1 分），第二名 GPT-6.1 Sol 搭配 Codex 为 0.969 分。参测的 11 套自研推理引擎中仅 5 套同时通过「完整生成规定长度回复」与「隐藏测试准确率」两道验收门槛。

总榜还显示运行框架的影响：同一款开源模型搭配 Codex 得 0.228 分、换 Claude Code 涨至 0.657 分，另一款则相反，说明模型与框架的匹配度会显著影响发挥。成本方面，仅开发阶段的 API 调用，Opus 5.5 花费 425.41 美元，高于前代 Opus 5 的 328.19 美元，约为第二名 GPT-6.1 Sol（84.52 美元）的 5 倍，GPU 与下游评测开销另计。

## 影响与后续观察

这项研究的直接意义在于量化了「智能体承担 AI 研发工程环节」的现实能力边界：在人类划定的单项任务里，前沿模型组合已能在推理引擎、调度、数据挑选等多个环节超过成熟的人类方案，这对推理服务成本与交互延迟的工程优化有直接参考价值。模型与框架组合产生的显著分差，也为智能体部署选型提供了新证据。

后续观察点包括：论文目前为预印本，六项结果的独立复现与评审情况待确认；各任务的硬件与时间预算限定较强，结论能否推广到更大规模、更长周期的真实研发流程仍属未知。研究者自己也指出，真正检验递归自我改进需要 AI 自主发现研发流程瓶颈、实施改进并把改进放回全流程验证，直至训练出经得起复测的更强下一代模型——这与本次「人类出题、AI 作答」的设定还有本质距离，属于待观察方向。
