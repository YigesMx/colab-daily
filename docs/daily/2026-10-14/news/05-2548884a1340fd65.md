## 事件概述

10 月 13 日，Anthropic 工程博客发布文章《Redesigning source control at Anthropic》：随着每日代码合并量从 2026 年 5 月的约 2500 次增长到 9 月的超过 3 万次（十倍以上），面向人类规模的开发者基础设施——源代码管理、构建与 CI——取代编码本身成为最大瓶颈。为此 Anthropic 自研了版本控制系统 Scion，并在五个月内将 monorepo 从 git 完全迁移过去；同期还交付了代码评审工具 Antique、代码搜索、细粒度源码 IAM 等配套系统。整个核心团队仅 7 人。

## 已确认事实与证据

- 规模数据（发布方披露）：主分支历史近 100GB，压缩工作副本超 25GB；每天为 CI 执行约 2500 万次代码检出，若按 git 朴素拉取将产生每天超 600PB 流量；此前 Anthropic 曾运维数百个内部 git 镜像应对负载（[官方工程博客](https://www.anthropic.com/engineering/redesigning-source-control)）。
- Scion 的核心设计与 git 相反：客户端始终在线、客户端-服务器不对称（服务端负责 diff、blame、提交、合并）、所有查询通过 API 暴露、全组件水平扩展且任何位置都没有完整仓库副本、无 packfile 维护；工作单元是写入前日志中的 changeset，配合内容寻址的 blob 存储与递归计算的派生数据（blame、路径历史、提交图跳表）；工作副本默认稀疏与虚拟化，许多 CI 任务可完全跳过检出。
- 部署形态为 scion-daemon / scion-cache / scion-server 三层缓存，底层存储为 Spanner；官方称各层缓存命中率超 99%，基础设施 CPU 与内存占用比原 git 镜像方案小 200 倍，CI 检出快两个数量级（分钟级变秒级），仅 CI 一项就释放了 25% 的 CPU 容量。
- Claude 深度参与：官方称用早期内部版 Claude Mythos Preview 重写 git 到 Scion 的摄取管道后，内存消耗降低 20 倍、速度提升 4 倍；工程师的角色转向高层设计取舍与"对 Claude 说不"的把关，每个变更仍经人工审阅（审意图而非逐行）。
- 对外定位：Anthropic 明确表示 Scion 不适合替代通用 git，仅在巨型 monorepo（数万工程师或大量智能体写代码）场景有意义；公司选择公开设计思路，并预计同类压力点将在未来 6–12 个月在更多使用 AI 编码工具的公司出现，希望与 GitHub、GitLab 及开源社区合作。

## 影响与后续观察

这是一份少见的"智能体规模软件工程"一手案例：AI 写代码的速度先压垮了为人类设计的工具链，而 AI 又被用来重建工具链。所有性能数字（200 倍基础设施缩减、25% CI 容量释放等）均为厂商自述，无第三方复现；Scion 及 Antique 均为内部系统，没有对外开源或产品化计划。后续可关注：其他重度使用 AI 编码的公司是否出现同样的 monorepo 压力、git 平台（GitHub/GitLab）是否会引入服务端 RPC 与新型协商协议，以及"合并队列在智能体时代是否还有意义"这类工程范式的进一步讨论。
