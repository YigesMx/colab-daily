## 事件概述

2026 年 9 月 24 日，量子位刊发由无问芯穹供稿的报道：清华大学联合无问芯穹打造并开源面向具身智能的云原生纳管平台 RLark。该平台以自研的具身设备运行时和任务级跨集群网络互联技术为核心，把机器人、相机等现场设备与云端算力统一纳入资源体系，以一项完整任务为单位组织运行。项目已在 GitHub（RLinf/RLark）与 Read the Docs（rlark.readthedocs.io）开放源代码与文档。

## 已确认事实与证据

以下事实经多个独立来源交叉核验：量子位报道正文（含无问芯穹提供的实测数据）、GitHub 官方仓库页面（其描述确认平台为跨集群具身智能云原生平台，基于 Kubernetes 原生 CRD、统一任务调度、跨集群 Pod 网络与多运行时支持）、Read the Docs 官方文档（含架构页，确认控制面、数据面、embodied-runtime 等模块存在）。

平台定位与目标。将云端算力、边缘节点和机器人、相机等具身设备纳入统一资源体系；让真实设备像 GPU 一样可申请、调度、复用；一份任务配置即可将训练、推理和真机交互程序部署到不同集群。GitHub 仓库描述亦确认其为"跨集群具身智能云原生平台"，采用 Kubernetes 原生 CRD 与统一作业调度。

官方披露的运行数据（无问芯穹口径）。平台已完成 3 个集群、近百个云边端节点的统一纳管，覆盖 4 种型号的具身设备；设备纳管耗时从小时级缩短至约 5 分钟；任务提交后 10 秒内启动。

跨地域真机实测。团队将 RLark 与强化学习基础设施框架 RLinf 结合，在广东云端 GPU 集群与北京机器人现场之间完成跨地域实测：现场机器人与相机负责交互与数据采集，云端 GPU 承担训练，RLark 负责设备申请、跨集群部署、任务实例互联与状态汇集。实验连续运行约 36 分钟，训练推进至 323 个全局训练步（global step），跑通采集—训练—真机验证闭环。相关技术论文《RLinf-USER: A Unified and Extensible System for Real-World Online Policy Learning in Embodied AI》发表于 RSS 2026（arXiv:2602.07837）。

通信优化专项测试。受限网络环境下，RLark 大包单流吞吐较测试所用 VPN 方案提升约 49%，小包提升约 14%；高带宽环境下大包单流吞吐接近 2 Gbps；与传统 EasyTier 方案对比，显著减少跨地域真机任务的网络卡顿。技术实现结合虚拟寻址、gVisor 用户态网络栈与 SSH 安全隧道。

技术架构（官方文档与报道一致）。控制面与数据面分离：用户经 Web 控制台、API 或 CLI 提交任务；各集群 Agent 负责本地部署与状态回传。四项核心：具身设备插件与运行时（把真实硬件注册为 Kubernetes 可识别资源）；任务级跨集群网络互联；声明式任务编排（Job/Task/Worker 三层模型）；任务级运行观测（沿任务—角色—执行实例逐层排查，提供 Web Terminal 与 TensorBoard 入口）。

## 影响与后续观察

对具身智能基础设施的影响。具身任务天然横跨现场设备、边缘与云端，此前需要逐台接入设备、分别部署程序、反复配置网络。RLark 把这些环节收敛为"一行命令接入设备、一份配置组织任务"，并使一次实验的接入与配置可在后续任务复用，直接降低多机器人机群研发的工程成本。开源范围覆盖从用户界面、API、后端服务到任务编排、跨集群互联和具身设备运行时的整套能力。

需要区分的口径。"5 分钟纳管、10 秒启动、49% 吞吐提升"等数字均为无问芯穹在自有测试环境（"资源已接入且具备运行条件的测试环境"）的披露，属于发布方数据，尚无第三方复现报告。

后续观察点。其一，机器人与芯片厂商的设备适配进度、社区贡献情况——官方在文末邀请厂商与算法团队参与，具体名单当前材料未确认。其二，更大规模（超过 3 集群、近百节点）下的调度与异常恢复表现——原文未报告。其三，与同类机器人云平台/算子方案的横向对比基准——原文未报告。
