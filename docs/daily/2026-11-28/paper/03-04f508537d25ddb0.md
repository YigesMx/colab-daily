## 研究问题与贡献

计算机使用智能体（computer-using agent）被期望完成真实用户目标，而不是孤立的界面动作。现有基准通常把 web、移动端、桌面环境分开评测，难以回答一个问题：单一的通用智能体能否在多个操作系统与持久应用状态之间完成长程工作流。OS-Omni 的回答是构建一个活的（live）跨平台基准与执行环境，覆盖 Windows、Ubuntu、macOS、iOS、Android 与 Web 六类环境，并用最终系统状态而不是中间视觉进度来判定成功。

论文贡献：提出按 300 任务一批（v1、v2 等）版本化发布的活基准（v1 含每平台 48 个任务与 12 个跨平台工作流）；设计以状态追踪、跨应用协调与最终状态正确性为核心的长程工作流；建立统一评测框架（可复现初始化、原生动作后端、轨迹记录、可执行最终状态评估器）；在 v1 上评测九个模型，显示最强的 Claude Opus 5.5 平均成功率 68.5%，仍落后人类参考 8.8 个百分点。

## 方法与系统

基准任务由自然语言指令、可复现初始化流程、平台适配器与最终状态评估器构成。环境基础设施包括：平台运行器按执行规范实例化对应运行时并运行智能体循环；状态重置按平台实现（Linux 恢复干净虚拟机快照、Windows 还原 golden 虚拟机存储、macOS 从基线 Tart 虚拟机克隆、iOS 克隆模拟器、Android 通过 ADB 重置应用与设备状态），先恢复平台基线、再物化任务数据、最后布置应用窗口。评测在智能体循环结束后调用任务声明的评估器检查最终环境状态，可解析办公文档、检查应用数据库、校验外部存储与领域应用状态；基准同时记录轨迹与评测记录，并提供 oracle 任务变体用于调试。

观察空间支持纯截图、纯无障碍树与两者结合三种模式，主实验采用纯截图（所有平台可用且最统一）。动作空间是两层设计：基础层是平台无关的类 PyAutoGUI 语义（指针、键盘、文本输入、滚动、拖拽、触控手势、等待、DONE 与 FAIL 终止决定）；定制层把高层动作意图映射到各平台最可靠的原生后端（Linux 的 PyAutoGUI 桌面事件、Windows/macOS 运行时调用、Android 的 ADB tap、iOS 的 Appium/XCUITest）。

为覆盖依赖商业服务的真实工作流，作者开发了 18 个自制“Open 系列”应用，支撑 v1 中 180 个任务（60%）：九个跨平台受控应用（OpenNote 社交笔记、OpenShop 电商、OpenTwitter 社交、OpenBank 网银转账与交易争议、OpenDriver 网约车、OpenTrip 机票酒店、OpenFood 外卖、OpenNavigation 路线、OpenPhotoEdit 图像编辑）与九个托管在 Linux 上的浏览器应用（OpenDoc、OpenSheet、OpenSlide、OpenMail、OpenFinance、OpenCode、OpenBlender、OpenWireshark、OpenZotero）。

## 实验设置与数据

v1 共 300 个任务：六个平台各 48 个，另加 12 个跨平台工作流（Ubuntu 或 Windows 桌面上通过 scrcpy 窗口显示一台 Android 手机，智能体需在两台设备间移动文件并回传结果）。任务类别分为日常生活 138（46.0%）、专业生产力 59（19.7%）、跨应用工作流 53（17.7%）、Web 任务 50（16.7%），共 34 个二级类别。数据构建由 30 名计算机专业研究生耗时两个月完成，标注约 2400 人时、复核约 400 人时；采用五阶段标注流程（经验化任务设计、独立复核、跨平台难度校准、oracle 执行验证、失败态测试与修订）。人类研究显示任务平均需要 67.54 次交互与 200.97 秒，明显长于 OSWorld 参考任务的 15.0 步与 111.94 秒。评测九个模型：GPT-6-Astra、Claude Opus 5.5、Gemini 4 Argon、GLM-5.3-753B、Kimi K3、Qwen 3.8 Max、Qwen 3.8 27B、Qwen 3.8 9B、DeepSeek V4.1 Flash；默认智能体接收当前截图与最近三张截图。

## 结果、限制与结论

论文报告：Claude Opus 5.5 取得最佳宏平均成功率 68.5%，比人类参考 77.3% 低 8.8 个百分点；其后为 GPT-6-Astra（66.1%）与 Gemini 4 Argon（58.6%）。按任务等权的微平均下 GPT-6-Astra 与 Claude Opus 5.5 几乎打平（67.0% 与 66.7%，即 201 与 200 个任务）。其余模型差距明显：DeepSeek V4.1 Flash 30.4%，Qwen 3.8 Max 13.1%，Qwen 3.8 27B 与 9B 几乎不能解题（1.2% 与 0.0%）。平台间极不均衡：人类在所有平台稳定于 72.6% 至 83.3%，而 Gemini 4 在 Linux 达 95.8%、iOS 仅 18.8%；Claude Opus 5.5 从 Linux 的 85.4% 到 iOS 的 41.7%；三个前沿模型在 Linux 上都超过人类的 74.6%，但 iOS 与 macOS 上最好成绩仍分别落后人类 33.5 与 25.6 个百分点。跨平台工作流上 Claude Opus 5.5 达到人类的 83.3%，GPT-6-Astra 与 Gemini 4 分别只有 58.3% 与 50.0%（该分组仅 12 个任务，每个任务影响 8.3 个百分点，需谨慎解读）。错误分析归纳四类失败：视觉定位错误、状态追踪错误（跨应用丢失复制信息）、持久化错误（界面看起来正确但最终状态未按评估器要求保存）、平台与时机错误（模态对话框、加载延迟、缺少确认步骤）。

限制：论文指出两点核心结论性局限——单平台强不代表通用性，以及“走得完界面”不等于“完成任务”（OpenBank 中智能体重复提交同一笔转账，OpenTrip 中创建五个预订却有重复与遗漏）。此外 Windows 任务因版权需用户自行激活，macOS 与 iOS 任务需要 Apple 硬件；跨平台分组任务数较少。结论认为通用计算机使用需要跨平台的持续状态维护与不同交互约定的适应能力，未来版本将继续以 300 任务一批扩展应用覆盖与难度。
