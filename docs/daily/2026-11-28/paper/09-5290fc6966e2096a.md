## 研究问题与贡献

上下文工程（context engineering）通过构造指令提示或元数据来引导大语言模型，无需大量训练。越来越多 LLM 上下文工程（LCE）方法把 LLM 本身当作“工程师”，从离线试错中提炼可泛化的指令或经验写入上下文。但这类方法究竟何时、如何有效，一直缺乏统一条件下的系统检验。本文的问题正是：LLM 能否从数据中工程出有效的上下文？

论文贡献：建立一个覆盖不同推理模式数据集的统一基准（LCEBench），在相同评测协议下对比多种 LCE 方法与多个 8B 级模型家族；评估参数规模与模型代际的缩放效应；通过新消融与案例研究揭示 LCE 何时、如何起作用。核心结论：没有单一 LCE 方法在所有任务上稳定胜出（甚至不敌思维链等简单基线）；缩放无法逆转 LCE 的失败；LCE 的增益与推理轨迹失败模式的多样性呈显著负相关（r 等于 -0.5，p 不超过 0.05）。

## 方法与系统

统一框架把 LCE 形式化为一个在文本空间上的优化循环：从训练 rollout 中提取经验、整合为上下文（系统提示或经验池），冻结的 LLM 再用该上下文执行任务。评测的方法覆盖两类：TextGrad 与 GEPA 面向系统提示工程（文本梯度反传、文本反思加变异采样）；TF-GRPO 与 ACE 面向经验蒸馏（TF-GRPO 用组相对的文本优势反思轨迹差异，ACE 维护带元数据的结构化 playbook 并做增量更新与去重合并）。基线包括思维链（CoT）与上下文学习（ICL，为每个测试样本随机选三条成功轨迹做演示）。

分析工具：用 LLM 对每条失败推理 rollout 归纳失败模式（要求可泛化、有证据），以 all-mpnet-base-v2 嵌入并用 Vendi Score 量化失败模式多样性（数值可解释为有效不同样本数）；对经验文本的多样性跨迭代跟踪；并做方差分解（数据集、模型、LCE 主效应）与混合效应分析。

## 实验设置与数据

任务覆盖五类：数学推理（MATH500）、多跳推理（HotpotQA）、指令遵循（IFBench）、检索（MiddleMatch）与智能体任务（AppWorld）。模型为 8B 级三家族：Qwen3-8B、Gemma4-8B 与 Min3-8B；每项实验用 5 个固定种子重复 5 次。缩放实验把“反思者”（生成反思工程上下文的模型）与“生成者”（用优化后上下文执行任务的模型）在 8B 与 32B 间独立变化；再从 Qwen3-0.6B 到 Qwen3-235B-A22B 联合缩放自反思模型，并横跨 Qwen1.5-7B 到 Qwen3.5-9B 五个连续代际比较。代码与基准发布于 github.com/costa-nus/LCEBench。

## 结果、限制与结论

论文报告：训练阶段 LCE 通常能提升验证性能，但测试期没有全能赢家——例如 Qwen3 上 GEPA 在 MiddleMatch 带来 +12.53 的显著提升、Gemma4 上 TF-GRPO 在 MiddleMatch +10.80，但在 MATH500 上 ACE 使 Qwen3 下降 7.30，HotpotQA 上 GEPA 与 ACE 分别使 Qwen3 下降 1.54 与 3.26；Gemma4 的 MATH500 上 TF-GRPO +6.10、GEPA +3.50。缩放实验显示更大或更新的模型不必然让 LCE 更有效：更大的反思者在 IFBench 与 MiddleMatch 多数设置更好，但在 MATH500 与 HotpotQA 上可能更差；从 0.6B 到 235B、从 Qwen1.5 到 Qwen3.5，基线任务能力普遍增强而 LCE 增益无一致趋势。机制分析：(1) 失败模式多样性越低 LCE 增益越大（GEPA 与 TF-GRPO 显著，ACE 因增量累积保留知识而相关性较弱），ICL 的增益与多样性无关，说明关键在“对失败的反思”这一操作；(2) 经验的 Vendi Score 跨迭代几乎不变，说明 LLM 无法通过迭代把多样失败蒸馏为共享原则；(3) 方差分解显示失败模式多样性主要来自数据集而非模型（如 MiddleMatch 用固定模板生成查询、失败高度同质）；(4) 案例研究显示部分增益来自指令遵循的改善（HotpotQA 上减少冗长答案造成的“假失败”、MATH500 上提高 boxed 格式合规率），用 LLM 抽取器标准化答案抽取后 LCE 增益明显缩水；(5) TF-GRPO 消融表明经验提取（E）是最关键环节，随机混入全部经验的变体先于其他因素决定成败，且更短的经验因上下文更短而更有效。

限制：论文自述其分析聚焦 8B 级模型与五个数据集，虽做了 32B 反思者/生成者与代际缩放，但更大规模的系统覆盖未报告；LCE 的改进路径本身仍是开放问题。结论给出三条指导：方法应在多样模型与数据集上验证泛化；开发应聚焦“从多样失败中提取有用经验”这一瓶颈；未来应探索按需注入知识以控制上下文长度。
