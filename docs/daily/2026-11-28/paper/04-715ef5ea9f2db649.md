## 研究问题与贡献

视频生成模型越来越多地被当作“视觉推理器”评测：给定首帧与自然语言提示，模型要生成把指定任务执行出来的视频。这一范式被认为具有“原生”优势——推理直接发生在画面中而非语言或代码里。这篇论文第一次在完全相同的条件下把这条原生路径与符号替代路径对撞：不是让模型去噪像素，而是让编程智能体写一个渲染答案视频的程序，再交给未修改的官方规则评测器打分。结论一句话：在 VBVR-Pro-Bench 上，编程智能体明显强于视频生成模型——三个闭源智能体得分 0.923、0.894、0.893，比最强视频模型高出 0.22 以上。

论文贡献包括：受控的媒介对照实验（相同输入、相同输出容器规格、相同官方评测器）；对 23 个可运行开源模型的效率与交付失败分析；以及对 1,385 个求解程序的两类推理策略（depictive 描绘式与 propositional 命题式）的行为学分类。

## 方法与系统

协议设计：每个实例在全新容器中运行，只包含该实例的输入与一份结构统一的任务说明（输出格式按实例变化）。智能体收到的约束是：写程序渲染答案视频；不得调用任何图像或视频生成模型；只允许改变提示要求的内容；动作必须在整段视频内展开。沙箱为仅 CPU 的 Python 环境（标准成像与科学计算库、预装字体），以非特权用户运行，固定资源限制与 30 分钟墙钟预算；允许网络用于模型 API 与装包。每实例一次尝试、不重试；退出时没有视频记零分。禁用生成模型这一点通过对每个事件日志与保留程序的审计确认。

智能体：三个闭源命令行编程工具按官方非交互模式、绕过审批、默认设置运行（不加系统提示或技能）：Codex CLI 0.154.0（gpt-6-astra）、Claude Code 2.1.268（Claude Fable 5.1，Amazon Bedrock）、Gemini CLI 0.59.0（gemini-3.1-pro-preview）。开源模型通过 OpenCode 开源编程智能体框架驱动 24 个模型（DeepSeek R1 在 Bedrock 上不支持工具调用，标记为不支持，实际计分 23 个）。

基准：VBVR-Pro-Bench，100 个任务族乘每族 5 个实例共 500 例，输入为 1024 乘 1024 首帧加任务提示。五个认知类别为感知（39 族）、抽象（25）、知识（20）、变换（19）、空间（17），多标签任务族按 1/k 加权计入各类别。评分用未修改的官方评测包，以经典计算机视觉与 OCR 对照符号真值给出 0 到 1 分；视频模型分数取自已发表的 VBVR-Pro 排行榜，未重跑。

## 实验设置与数据

比较对象覆盖 37 个系统：3 个闭源编程智能体、23 个可运行的开源编程智能体、以及已发表排行榜中 14 个视频模型里得分最高的 11 个。效率度量来自智能体 CLI 的机器可读日志：工具调用次数、输入输出 token（跨智能体仅作参考）、墙钟时间中位数；并记录是否调用过工具、是否超时。策略分类通过行为学方法完成：把闭源智能体解出自己实例的 1,385 个程序在同一任务族的不同实例上重新执行，若程序能通过导航图像（颜色过滤、区域测量、物体定位）在运行时恢复答案则归为描绘式，若只渲染智能体会话中预先确定的硬编码值则归为命题式。

## 结果、限制与结论

论文报告：三个闭源智能体占据总榜前三并全部交付 500 个视频，Codex（gpt-6-astra）0.923、Claude Code 0.894、Gemini CLI 0.893；最强视频模型 VBVR-Pro-Wan2.2-I2V-A14B 是用基准任务族与评测器作为可验证奖励做强化学习训练的，得分 0.670，与 Codex 差 0.253，其后 VBVR-Pro-Wan2.1-I2V-14B 再低 0.108。最好的开源模型 GLM-5 得 0.572（交付 495 个视频），超过除强化学习模型外的所有视频模型；Kimi K2.5 得 0.557。类别上三个闭源智能体在全部五类都超过 0.8 并在每一类领先，感知类差距最大、变换类差距最小（作者提醒感知类任务多为定位与测量，规则代码可精确执行，优势被放大；变换类则可能是视频模型从视频数据中更自然获得的能力）。开源模型的类别轮廓不同：感知是其最强类别、抽象差距最大。交付失败是开源低分的主因（分数与交付视频数 Spearman 相关 0.93）：Gemma 3 27B/12B、Llama 3.3 70B、Magistral Small 从不调用工具；Qwen3-32B 与 Llama 4 Maverick 过早终止（分别只交付 25 与 7 个视频）；Qwen3-Coder-Next 在 93 个实例上超时但基本都先写出了视频。三个闭源智能体得分仅差 0.030 而成本差近一个数量级（Claude Code 约 3 倍工具调用与 4 倍输入 token，Gemini CLI 约 8 倍调用与 12 倍 token）。策略分析：描绘式程序在感知类占 67%、变换类 45%；命题式在知识、抽象类占比最高；两种模式都不能预测得分。

限制（论文自述）：VBVR-Pro 任务由代码生成渲染，平涂色彩、精确几何、确定性评测器，程序化求解天然有利；真实世界中物体有纹理、遮挡与光照变化、没有符号真值，结论不能直接外推；比较也不对称——智能体有工具、沙箱与最多 30 分钟迭代，视频模型只采样一次，且智能体成本跨系统差异巨大；作者也强调这是对现状的描述，并不构成视频生成模型原则上限的证明。
