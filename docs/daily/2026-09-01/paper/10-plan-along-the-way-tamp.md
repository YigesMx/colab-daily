# Plan Along the Way: Event-Triggered Foundation-Model Planning for TAMP Execution in Partially Observable Manipulation

**一句话结论：** IIIT Hyderabad 团队提出 ROBUST TAMP——一个模块化的 LLM/VLM 引导任务与运动规划（TAMP）框架，把"发现新物体"作为一等重规划事件，在部分可观测的操作任务中让基础模型规划器只基于当前可见场景状态规划、在交互揭示隐藏物体后重建状态并重规划，仿真实验显示 8B/32B 规模模型在该框架下平均任务成功率超过 86%。

## 研究问题与贡献

长时程机器人操作经常处于部分可观测环境：任务相关物体可能一开始被遮挡（如关在容器里的杯子），只有通过交互（打开容器）才变得可见。论文指出一种不同于常规"执行失败"的失败模式：初始计划对可见场景而言是有效的、也能成功执行，但由于交互过程中出现了此前隐藏的任务相关物体，该计划对任务完成而言不再充分。已有的基础模型引导 TAMP 系统大多假设场景状态完全给定，或只在子目标/执行失败后触发模型级重规划，没有把"新物体被发现"单独建模。

这项工作与核心方向（具身智能、机器人操作规划、基础模型在机器人任务规划中的应用）直接相关。论文声明的主要贡献包括：

1. **仅可见物体的规划形式化**：规划器只接收当前可见关系场景状态，利用场景常识与几何推理合成可执行动作，减少整体 TAMP 重规划次数；
2. **事件触发重规划**：把新揭示的场景物体纳入规划，让 FM 规划器推断被发现的物体如何改变任务需求；
3. **分层失败升级架构**：结构性非法计划在执行前被拒绝，可恢复失败在执行后端内部处理，只在确需系统级重规划时才带着结构化失败上下文调用 FM；
4. **跨场景、提示方式、模态与模型规模的基础模型能力定量与定性评估**。

## 方法与系统

ROBUST TAMP 的核心设计包括：

- **可见规划状态与规划事件**：规划发生在离散的规划事件 k 上。规划器可见上下文 c_k = (s_k^vis, h_k, e_k, g)，其中 s_k^vis 只包含当前可见物体集合 V_k、观测到的区域归属、可用放置区域、机器人状态与容器开合状态；h_k 是已执行动作历史；e_k 是结构化事件上下文（新发现物体或未恢复的执行失败）；g 是自然语言目标。未观测到的物体无论是否与目标相关，都明确排除在规划证据之外，直到交互使其可见。状态被描述为轻量级关系场景图，每次重规划时从当前证据重建，而不维护包含未观测物体推断状态的持久几何世界模型。在 RLBench/CoppeliaSim 实现中，可见性由分割掩码提供，几何信息来自仿真器特权查询，作者明确说明这是为了把规划/重规划行为与感知误差隔离。
- **严格的可执行接口与分层校验**：FM 规划器输出任务级动作序列（如厨房域的 pick(o)、place(o,r)、open(c)），执行前由受限解析器校验动作、物体、区域是否属于可执行接口及序列结构（如孤儿 place、持物时 pick 等，见论文失败模式分类表 Table I）。结构校验与场景相关校验（可见性、可达性、前置条件）分层：前者在执行前拒绝，后者在闭环执行中检测。非法序列被拒绝并生成结构化失败上下文用于重规划。
- **异构落地执行**：通过校验的序列送入执行层，执行适配器 X_d 可将 pick-place 等动作捆绑以保持物理上下文；不同动作可由 PDDLStream 运动规划、几何辅助或固定运动原语分别实现，不要求统一落地机制。
- **闭环监控与分层失败升级**：执行后端先以局部兜底（替代抓取采样、替代轨迹、场景特定恢复例程）处理可恢复失败，不触发 FM 调用；执行后监控层验证意图状态变化（如物体是否出现在目标区域）。未恢复失败被转换为结构化事件反馈给规划器。
- **发现触发重规划**：新物体出现被当作独立重规划事件，即使此前执行完全成功。在稳定执行边界处中断当前序列，重建可见场景状态，由 FM 结合完成动作历史与结构化发现上下文生成修订的剩余动作序列。

## 实验设置与数据

- **环境**：RLBench/CoppeliaSim 仿真，3 个厨房变体（K1–K3）与 3 个烧烤变体（G1–G3），共 6 个场景，含隐藏物体、非目标物体发现、关节容器交互与时序操作程序。厨房任务目标为"把所有杂货放进橱柜、所有杯子放进容器"；烧烤任务要求"用烤架烹饪所有生肉并装盘"，G1/G3 还含一部非目标手机，期望行为是在没有显式指令的情况下把它挪到桌上。
- **模型后端**：同一管线下可互换比较 6 个基础模型规划器：Qwen3-4B/8B/32B（纯文本 LLM）与 Qwen3-VL-4B/8B/32B-Thinking（VLM，每次规划事件额外接收新拼接的多相机 RGB 图）。温度 0，最大生成长度 4096 token，模型托管于两块 NVIDIA RTX 4090，经 Hugging Face 库与远程规划服务器调用。
- **协议与指标**：每个"模型×变体×提示条件"组合独立运行 10 次试验；对比 zero-shot 与 ICL（场景无关的正负示例）提示。指标包括任务成功率 TSR（基于确定性完成谓词 G_τ：厨房验证最终物体-区域关系，烧烤额外验证烹饪时序谓词）、部分目标完成率 PGC、隐式非目标处理率 INH（仅 G1/G3，未被提示情况下把手机移到桌上的比例）、重规划行为（FM 调用次数与重规划循环数，发现触发的重规划单列）与规划器调用延迟。重规划预算为 10 次。

## 结果、限制与结论

以下为论文报告的结果（本次精读基于 arXiv TeX 全文，表格数值逐条来自论文 Table II）：

- **RQ1（发现触发重规划）**：作者指出由于场景的隐藏物体设计，没有事件驱动重规划框架时任何 FM 的 TSR 都为零。在 ROBUST TAMP 下，8B 与 32B 模型的平均 TSR 超过 86%；4B 模型 4 个条件中有 3 个平均 TSR 超过 66%。最低的 4B LLM zero-shot 条件平均 TSR 26.7%，但 PGC 达 42.5%，说明许多失败发生在部分完成之后。
- **RQ2（模态与规模）**：更大模型需要更少的失败触发重规划但调用延迟更高；8B 模型 TSR 与 32B 相当且计算更便宜，作者认为中等规模在成功率、恢复质量与成本间权衡最优。当规划器已获得显式物体-区域状态时，VLM 相比纯文本 LLM 没有明显 TSR 优势且延迟更高。
- **RQ3（ICL 与 INH）**：zero-shot 模型常完成显式任务却忽略新揭示的非目标手机（8B/32B LLM zero-shot 在 G1 上 TSR 100% 但 INH 0%）；ICL 使 8B 和 32B LLM 的 INH 达 100%，4B LLM 在烧烤变体上从 zero-shot 0% TSR 提升到 100%。作者据此指出现有模型过于聚焦显式目标、忽视可能有负面后果的非目标物体。
- **RQ4（主导失败机制）**：4B 小模型失败以解析器/可执行接口类错误为主；大模型更多满足接口约束，失败集中在执行落地、运动、放置与执行后验证。ICL 显著减少所有 LLM 的解析/接口失败。

**限制与证据缺口**：实验仅在仿真中进行，可见性与几何信息使用仿真器特权信号作为可靠感知的代理，真实机器人部署需要另加安全边界、感知模块与鲁棒执行后端，论文未做真机验证；评测规模较小（每条件 10 次试验），只覆盖 Qwen3 系列模型；代码、数据与项目页在原文中未见报告。VLM 相比 LLM 无优势这一结论是在"规划器已拿到显式物体-区域关系状态"的前提下得出的，不能外推到需要从原始图像自行感知场景的设置。

**对组内的启示**：事件触发重规划与"仅可见状态"接口是部分可观测长时程操作的可行工程范式，其失败分类学（结构校验/场景校验/执行恢复分层）和 INH 这类隐式非目标处理指标，可直接借鉴到组内 VLA/操作系统的规划监控与评测设计；8B 量级模型在带严格接口校验的管线中即可获得较高成功率，对端侧或低成本部署有参考价值。
