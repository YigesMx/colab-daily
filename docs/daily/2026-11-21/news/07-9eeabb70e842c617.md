## 事件概述

2026 年 11 月 20 日，Hugging Face 在官方博客发布《Introducing harness adapters》，提出"harness adapter"（智能体框架适配器）方法：不改动基础模型权重，而是在你实际使用的智能体框架（agent harness）内部用强化学习训练一个 LoRA 适配器，使模型"适配框架"，在同一框架与任务分布下同时获得更高准确率与更低成本。官方以 Qwen3.8-27B 为例：在 pi 框架下 Terminal-Bench 2.1 成绩为 39%、平均每任务 2900 token；冻结权重、加上经 RL 训练的自定义 LoRA 后达到 55% pass@1，平均 token 用量降至约 1500。

## 已确认事实与证据

以下内容均出自 Hugging Face 官方博客（2026 年 11 月 20 日）：

- 训练设置：为 pi（1.5.2）、OpenCode（2.2.7）、Hermes Agent（v0.22.6）三个框架各训练一个 LoRA 适配器，RL 训练直接在框架本身内进行（借助 Harbor/OpenEnv 与 TRL 的 AsyncGRPOTrainer，数据集、训练与智能体 rollout 全部在 Hub Jobs 上完成）；每个框架使用 2 块 B200 GPU（一块跑 vLLM 服务、一块训练）。
- 任务数据管线：对 Hub 上约 5.9 万个 Harbor 任务去重过滤后，保留 SWE-smith（注入缺陷的真实 Python/Go 仓库）、SWE-Gym（真实 GitHub issue）、自建 Tasksmith（从合并 PR 生成任务）三类来源；openenv validate 语义校验后 1127 个候选中 858 个通过；再经基础模型难度筛查（Qwen3.8-27B 每任务尝试 4 次，442 个计分任务中"有时能解"的 171 个构成合格集）；最终数据集 harness-hub/agentic-coding-envs 共 871 个任务、35 个仓库；最终训练混合 750 个 harness-adapters 环境任务与 300 个 termgrade 任务。
- 超参与奖励：学习率经 50 步扫描后定为 2e-5；奖励为验证器通过与否加 0.1 的工具效率加成；训练中接入 safeagents 拦截不当行为，三轮训练共检查 130 万次工具调用、拦截 647 次。
- 专家适配器成绩：SWE-bench Pro（最难 51 题）上，pi 从 39.2% 升至 64.7%（+25.5 个点，p=0.002）、hermes 从 29.4% 至 43.1%、opencode 从 35.3% 至 51.0%；Terminal-Bench 2.1 全量上，pi +16.3 个点、hermes +14.1 个点；在双方都能解的任务上，工具调用次数减少 53% 至 70%。
- 超级适配器：三个 LoRA 沿秩维度拼接合并（秩 96），合并权重 1/2 效果最佳；思考模式关闭时在全部六个"框架-基准"组合上超过基础模型（平均 pass@1 从 39.5% 到 49.0%）；未用思考模式训练过，却在思考模式下于六个组合中五胜一平（平均 55.5% 到 63.5%）；每任务工具调用减少 53% 至 73%、token 减少 44% 至 60%。
- 跨框架迁移与分布外：pi 适配器在 OpenCode 下与原生 OpenCode 专家基本持平，在 Hermes 下保留约三分之二增益；在 300 个 AutomationBench 业务自动化任务（使用其自带智能体循环）上各适配器与基础模型差距在噪声范围内，未见明显迁移也未受损。
- 开放产物：三个专家适配器、超级适配器、GGUF、RL 任务与 safeagents 插件均通过 Hugging Face 合集公开，模型轨迹亦公开，供复现。

官方同时披露两点保留：合并权重 1/2 是在 Terminal-Bench 2.1 上选定的，该基准数字"略乐观"；分析轨迹发现非思考模式下模型会先输出简短文本再调用工具（一种"推理泄漏"），官方认为不改变结论但提出了后续对纯思考与混合思考模型复现的问题。

## 影响与后续观察

- 该方法把"模型-框架-任务"联合优化变成可复用的开源配方，对依赖开源模型构建编码智能体的团队是直接的工程收益：固定框架下以 2 卡 B200 级别的训练即可获得两位数百分点的基准提升与近半的成本下降。
- 社区反馈（官方转述）称适配器在 Qwen3.8 衍生模型（如 Swift-1.5）上也有效，官方标注为开放问题；衍生模型上的泛化性待独立验证。
- 评测均为 Hugging Face 自报（HF 沙箱、每任务单次尝试、温度 0.8），且不同框架间设置差异导致不可横向比较，采纳数字时应注意口径。
- 后续关注官方预告的方向：更多模型上的复现、混合思考/非思考训练策略，以及第三方在真实业务仓库上的复现结果。
