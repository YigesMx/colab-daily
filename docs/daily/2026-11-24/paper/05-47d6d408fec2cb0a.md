## 研究问题与贡献

前沿视觉-语言模型越来越多地作为机器人智能体运行：解读场景、分解任务、通过工具调用协调执行。常见做法是把预训练操作策略封装成可调用技能，智能体只在调用返回后才被再次唤醒。这种回合制接口在策略运行期间把智能体锁在门外：人在策略执行中途走进机器人路径、或移走它正要抓的物体时，智能体对扰动一无所知，直到控制权交回。论文的量化观察很直观：给 RoboCasa365 任务加入反应式人类化身后，四个预训练策略（三个 VLA 和一个 WAM）都损失过半成功，最强的 Xiaomi-Robotics-1 从 61.9% 跌到 20.8%，约半数回合碰到人。更频繁地唤醒智能体则代价高昂——每次高层决策要数秒的推理。作者的洞见是：守望场景并不需要强推理，"有人靠近"是紧凑 VLM 加深度图零点几秒就能解决的感知问题；真正需要智能体的是"什么变化该打断我"的判断，而这个判断随智能体最近的决定而变——判定路人无碍后恢复策略，只需知道人是否逼近；选择等待后，则只需知道人何时离开。

TRIP 的贡献有三：一个免训练、策略无关的执行框架（harness），让智能体给自己编程中断——有状态的绊线（tripwire）程序在策略执行期间查询紧凑 VLM、结合深度与记忆做计算，并随局势更新；RoboHD 人类扰动基准，在 42 个 RoboCasa365 任务上构建 168 个场景，任何人人接触即判失败；覆盖三个 VLA、一个 WAM 与真实机器人的实验，包括与同智能体、同工具、同提示词的回合制基线的配对比较、绊线更新消融与真机扰动试验。

## 方法与系统

TRIP 的执行循环如下：给定指令，智能体选择一次执行调用（运行预训练策略、直接控制底盘/臂/夹爪运动、或原地等待）并附上一条绊线。绊线是一个 Python 函数，输入当前观测与记忆，输出下一步记忆和False或一个文本触发原因（如"人距 0.6 米、以 0.3 米/秒接近"）。观测包含五路 RGB-D 图像、机器人掩码、夹爪与底盘位姿以及执行元数据（当前调用、已用时间、上次触发的时间与原因）。绊线既能"看"也能"算"：它自选相机视角、问题和查询频率，通过 vlm(问题, 图像) 接口查询一个冻结的紧凑 VLM，把短回答与几何测量和时间信息结合——预测的图像位置加深度给出人相对机器人的位置，连续估计显示人是否在接近；配合计时器、步数计数与逻辑条件，一条绊线可同时监视任务进度、意外出现或目标物被移动。触发时框架立即停止调用并让机器人保持静止（停顿不等待智能体推理），随后唤醒智能体，把原因、绊线记忆与当前图像交给它重新决策；智能体可保留或改写绊线以匹配其响应（例如从"监视人靠近"改为"监视人离开"）。绊线在沙箱中运行：只允许 numpy/math/json/re/statistics 模块、无文件与网络访问、源码至多 6000 字符、每次检查至多两次 VLM 查询（回答至多 64 token）、4 秒内必须返回、记忆上限为每相机两帧图像与深度；静默的策略调用 60 秒后停止。智能体是支持工具调用的视觉-语言模型（默认 GPT-6.1-sol），拥有观测、策略执行（用绊线取代固定时长）、直接动作、绊线编程与记忆检查五组工具。

策略保持黑盒，TRIP 不做任何微调即可包裹 VLA 与 WAM。论文还指出与三类已有监视方案的差别：VoLo 周期性轮询前沿模型；DoReMi 让小 VLM 回答规划器写下的语言约束是否成立，只能得是/否；Code-as-Monitor 在子目标起点跟踪几何状态、执行中不再发起新 VLM 查询。对人的反应需要两者兼备——发现写入检查时不在场的人，并从距离与运动判断其是否要紧。

## 实验设置与数据

RoboHD 基准选择 42 个 RoboCasa365 组合任务（PandaOmron 移动操作平台需在厨房设施间导航），每个任务构造四个场景、对应四类扰动共 168 个：空间扰动（人占据导航路径，如拖地，机器人需等待或绕行）、物体状态扰动（人移动目标物或容器，机器人需适应新位置）、任务状态扰动（人改变设施状态如关冰箱、开水龙头，机器人需恢复状态或调整计划）、感知扰动（人在 1 米内做无关活动，机器人需保持距离继续任务）。人类化身由脚本控制器驱动，经历空闲、接近、等待、行动、离开五个阶段，推进条件是机器人到达触发状态（抓放物体、底盘接近目标、门达到角度），因此化身对任务进度而非固定时间表做反应；动作来自 BONES-123 与 SEED 动作捕捉片段拼接。化身无碰撞体，接触判定是几何的：对人骨骼拟合胶囊、对机器人用包围盒，最小距离为零即算接触，任何接触都判失败。所有方法使用相同初始状态，并各自评测无人的参照场景。回合以智能体调用 finish、首次接触人、达到开销上限或 100 次工具调用结束；仿真中智能体与 VLM 计算时物理暂停（真机不暂停）。被评策略为 GR00T N1.5、REKI-2B、Xiaomi-Robotics-1 三个 VLA 与 PatchWAM 世界动作模型；回合制基线遵循 RPent 设置，智能体自选每次策略调用 1 到 16 秒的时长。绊线查询的 VLM 为关闭思考模式的 Qwen3.5-9B，每秒机器人时间约查询 2.2 次。真实实验用 UFACTORY xArm 7 加平行夹爪、两台 RealSense D455（第三方与腕部），两个单任务 π0.5 行为克隆策略（挂马克杯、挂毛巾）各用 100 条遥操作示范训练，策略跑在一张 RTX 4090 上、绊线 VLM 跑在另一张上，每任务 10 种桌面布置、三种条件（无扰动/挡臂/移走目标物）。

## 结果、限制与结论

仿真主结果：有人扰动下，TRIP 相对裸策略全面提升成功率——GR00T 从 3.0% 到 6.5%、REKI-2B 从 13.7% 到 22.6%、PatchWAM 从 18.5% 到 24.4%、XR 从 20.8% 到 38.7%；相对同配置回合制基线，TRIP 在 REKI-2B、PatchWAM 和 XR 上更高（XR 为 38.7% 对 31.0%）。由于两种智能体方法的差别只在唤醒时机，增益可归因于绊线在整个调用期间持续监视人。安全性（可解场景中无接触回合占比）上 TRIP 对每个策略都更高，XR 达到 81.3% 对基线 61.3%，人接触率减半；无扰动时两方法对各策略的提升幅度相近。效率上，TRIP 的智能体每分钟机器人时间只做 19.4 次工具调用（基线 30.3 次），看场景的调用从每回合 28.7 次降到 10.1 次——守望工作由每分钟触发约 10.3 次的绊线承担；智能体平均每回合写 4.2 条绊线，物体状态场景最多（4.8 条）。消融显示绊线必须可更新：整回合保持智能体首条绊线使安全降到 61.3%、成功降到 33.3%；预定义的"人在 0.6 米内就停"绊线安全最高（86.0%）但成功只有 16.1%——靠一动不动换安全不可取。换用 GPT-6 Astra 做智能体，成功基本不变（38.1%），安全 73.8% 仍高于基线。真机上不暂停物理：绊线单次检查平均 0.24 秒（含约 1.4 次 0.17 秒的 VLM 查询），每秒读约 4 帧图片、匹配策略动作块的节奏；智能体一次决策平均 4.3 秒。真实结果鲜明：挡臂与移目标条件下，裸策略 10 次布置中最多成功 1 次、回合制基线最多 3 次，TRIP 达到 5 到 7 次，接近无扰动水平（挂毛巾任务 7/7/7）。

论文自述局限：人是脚本化化身、无碰撞体，大规模真人受试实验因安全不可行；仿真中智能体与 VLM 计算期间物理暂停，机器人时间未计入其延迟，一个 TRIP 回合的 API 开销约 0.2 到 0.3 美元、1.5 分钟机器人时间对应约 12 分钟墙上时间；受十倍 API 成本限制，只有 Xiaomi-Robotics 用了当前最强智能体 GPT-6 Astra。此外当前材料未确认官方项目页或代码发布。总体而言，TRIP 代表了一种务实的分工：把廉价高频的感知守望下放给紧凑 VLM 和几十行可执行代码，把昂贵低频的决策留给前沿智能体，用"自己写中断"替代"更频繁地思考"，在不重训策略的前提下显著提升人机共处场景的安全性。
