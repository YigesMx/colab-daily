## 事件概述

AI 编程工具公司 Cursor 于 2026 年 10 月 29 日发布安全公告： Anthropic 官方 Claude Code 扩展（Anthropic.claude-code）的 2.1.312 与 2.1.313 两个版本在 Cursor 的 VS Code 扩展市场中被恶意篡改，植入试图安装持久化 SSH 后门的恶意代码。据 Cursor 官方公告，恶意版本在当日太平洋时间约 2:27 至 13:35 间可被下载，持续约 11 小时；据 Ars Technica 报道及 AI Policy Daily 汇总，受影响用户「至多约 5000 人」。安全公司 Phorion 与独立研究员 Kevin Beaumont 指出，恶意版本是通过 Anthropic 在 Cursor 市场上的官方账号分发的，属供应链攻击，但两家公司当时均未说明攻击者如何获得账号权限。

## 已确认事实与证据

以下事实已通过 Cursor 官方安全公告原文确认：

- 事件涉及 Cursor VS Code 扩展市场中的 Anthropic.claude-code 2.1.312 与 2.1.313（Windows 与 macOS 版本）；Cursor 明确这两个恶意版本「并非由 Anthropic 开发」。
- 恶意代码会收集并回传主机与用户信息：主机名、用户名、操作系统、架构、主目录路径、环境变量名、工作目录、配置的 Git 邮箱与公网 IP。
- 恶意代码尝试向 authorized_keys 添加攻击者控制的 SSH 密钥、启用本地 SSH 服务并建立反向 SSH 隧道；在 macOS 上通过 LaunchAgent、在 Windows 上通过计划任务与启动脚本实现持久化，后台脚本约每 60 秒重试隧道连接。
- 公告指出，除极少数以管理员权限启动 Cursor 的情形外，由于恶意代码自身错误，启用本地 SSH 服务的步骤在多数主机上会失败；Cursor 已联合托管服务商将攻击者服务器下线，反向 shell 与信息回传已失效。
- 处置措施：Cursor 在发现后立即移除恶意版本、暂停整个市场、审计确认无其他扩展被篡改、轮换密钥并重建市场后恢复上线。
- 公告附带了 macOS（bash）与 Windows（PowerShell）两份官方修复脚本，本文证据目录已留存；公告提醒仅卸载扩展可能不足以清除感染，因为载荷会释放独立运行的持久化脚本，并建议轮换受影响主机可访问的凭证与会话。

以下事实经 Ars Technica 报道与 AI Policy Daily 汇总交叉印证（二手信源，官方公告未直接给出）：

- 受影响用户规模「至多约 5000 人」；Anthropic 在恶意版本出现数小时后推送了替代版本 2.1.314。
- Phorion 联合创始人兼 CTO Luke Roberts 称这是「攻击者获得官方分发渠道访问权的供应链攻击」；恶意版本经由 Anthropic 的官方账号发布，并利用扩展默认自动更新触达用户。
- Anthropic 表示自身系统未被入侵，问题出在攻击者获得了 Cursor 市场相关访问权限；截至报道时，两家公司均未解释攻击者如何获得该访问权。
- 环境变量名收集被认为可帮助攻击者快速盘点主机上的云凭证（Phorion 观点）。

## 影响与后续观察

这是 AI 编程工具供应链安全的一次标志性事件：攻击者并未攻破 Anthropic 或 Cursor 的代码仓库，而是劫持了「官方账号 + 默认自动更新」这条最可信的分发路径。对依赖扩展市场与自动更新的开发者工具生态而言，事件暴露出发布通道权限管理的薄弱环节——官方账号被接管后，市场机制本身没有拦截住恶意更新。

后续值得观察：Cursor 与 Anthropic 是否披露攻击者获得账号访问权的具体路径与责任归属；受影响约 5000 名用户中有多少实际执行了恶意载荷、是否出现凭证泄露的实际损失；Cursor 市场重建后的发布审核与账号安全机制有何变化；以及 VS Code 系生态是否普遍收紧对官方发布者凭据与多因素认证的要求。短期内，装过 2.1.312/2.1.313 的开发者应按官方指引运行检测与修复脚本并轮换凭证。
