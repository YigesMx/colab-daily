## 事件概述

随着Codex、Claude Code、Kimi Code等编程智能体开始支持"动态并发"——由主智能体在执行过程中自主决定何时创建子智能体并协调其工作——多智能体协作正在成为Coding Agent的主流方向，但其真实收益一直缺乏系统评估。据新智元2026年10月20日报道，南京大学与伊利诺伊大学香槟分校（UIUC）的研究人员对三种前沿Coding Agent开展了大规模配对实验，覆盖354个软件工程任务、2124次执行，并结合主智能体与子智能体的完整执行轨迹分析动态并发的收益、调度行为与失败模式。该研究论文发布于arXiv（编号2610.10263，标题为"When Sub-Agents Work in Parallel: The Promises and Pitfalls of Dynamic Concurrency"，arXiv摘要页已经抓取留存并确认）。

## 已确认事实与证据

据新智元报道，实验对比了三种系统原生并发机制：Codex Multiagent V2（主智能体继续执行的同时动态创建子智能体并经消息交换协调）、Claude Code Dynamic Workflow（动态生成工作流脚本组织多个有依赖关系的执行阶段）、Kimi Code AgentSwarm（批量委派不同目标的子智能体并行执行后回收结果）。评测覆盖RepoZero（代码仓库跨语言重建）、ProgramBench（按参考程序重实现）、NL2Repo（自然语言生成代码仓库）、LoopsBench（长周期持续工程任务）四个长周期基准，并引入SWE-bench Verified作为短周期任务对照；全部2124次执行记录约112亿token，按标准API价格约合20,780美元。核心结果：动态并发收益呈明显任务依赖性——LoopsBench上Claude Code完成率从7.1%升至21.4%、Codex从21.4%升至25.0%，NL2Repo上Codex从34.6%升至57.7%，但Kimi Code在NL2Repo反而从57.7%降至46.2%；SWE-bench Verified上Codex持平于71.0%，Claude Code从83.0%降至59.0%、Kimi Code从77.0%降至59.0%。整体上Codex并发模式多完成8个任务但未达统计显著，Claude Code与Kimi Code分别少完成42个和19个任务且下降显著。资源方面，并发模式token消耗为顺序模式的1.41至3.31倍，15组组合中14组平均运行时间反而增加。轨迹分析方面，研究对1062条并发轨迹人工标注，归纳出4大类、13个子类别、28种具体失败模式（出现在650条轨迹、804次实例中）：任务编排问题占28.5%（如伪并发、缺少负责人、负载不均）、执行治理问题占29.0%（如结果汇合时机不当、失败后工作丢失）、全局上下文管理问题占9.3%（如信息交接未被利用、接口约定不明）、共享状态与代码集成问题占33.2%（如并发写入冲突、共享环境污染）。研究同时总结了并发真正产生价值的三类机制：互补分工、并行探索多方案后择优整合、以及独立验证发现并修正错误。调度统计显示，Codex首次委派最早（中位数约位于全程4.0%处），Claude Code与Kimi Code分别为22.1%与26.0%；而至少两个子智能体同时存在的时间占比中位数，Claude Code达52.7%，高于Codex的23.9%与Kimi Code的15.6%。上述数字与结论均出自新智元对论文的报道，arXiv页面确认了论文标题与编号。

## 影响与后续观察

这项研究为"多智能体不等于更好"提供了迄今规模较大的实证依据：并发收益取决于任务可拆分性、主智能体的整合能力与共享状态管理，而非智能体数量；对开发者而言，在目标明确、修改范围小的任务上开启并发可能得不偿失，在长周期探索性任务上则有明确潜力。研究提出的28种失败模式分类与"互补分工、并行探索、独立验证"三类有效机制，可作为智能体系统设计与评测的参考框架。后续值得观察论文的同行评审进展、28类失败模式在更多系统上的泛化性，以及主流Coding Agent厂商是否会据此调整并发调度与结果回收策略；论文作者隶属机构与署名细节以arXiv正式版本为准，新智元报道中未逐项列出。
