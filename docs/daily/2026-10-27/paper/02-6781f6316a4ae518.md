## 研究问题与贡献

机器人基础模型的整个生命周期都依赖数据标签：部署监控需要结果奖励（outcome reward），RL 后训练需要过程奖励（process reward），预训练数据的过滤与配平需要带时间戳的描述（caption）。NVIDIA GEAR 团队指出，现有系统大多只覆盖其中一种标注类型，而用通用前沿模型做标注在大规模机器人数据上成本高到不可行。论文提出 Flora——一个用于训练 GR00T 系列模型的工业级机器人数据引擎，同时覆盖时间戳描述、过程奖励与结果奖励三种能力，并支持测试时由用户定义评分量表（rubric）的灵活奖励建模。

核心贡献包括：（1）由分割模型、描述模型与奖励模型组成的开放模型套件，在 WGO-Bench 描述基准与 RoboReward、Robometer 奖励基准上取得 SOTA，内部基准上与 GPT-6 Astra 具竞争力而显著超过其他前沿模型；（2）成本上比 API 方案便宜约 125 倍（对 GPT-6 Astra 最大推理档）；（3）经受住了大规模实战检验——在 512 张 GB300 GPU 上每天标注 20 万小时数据；（4）开源模型套件，支持社区扩展自定义机器人数据集以及物理自动研究（physical auto-research）、人-机迁移等新应用。

## 方法与系统

Flora 由三个微调自 Qwen3.5 家族的模型组成：分割模型（Qwen3.5-9B 初始化，LoRA 微调、视觉编码器冻结）、描述模型与奖励模型（均为 Qwen3.5-27B 初始化）。

### 带时间戳的描述流水线

给定时长为 T 的视频，输出 (起点, 终点, 描述) 三元组列表。流水线把视频切成带上下文的重叠窗口，分割模型预测窗口内的时间区间与跨界标志，经确定性过滤和跨窗口缝合（stitching）得到片段级区间，再用边界细化。描述模型对每个区间生成一条自包含的祈使句描述，输入包含目标区间前后的邻近帧（显式标注 before/target/after 块），多相机录制会把同步视角拼成一张图；提示要求描述意图动作、物体、执行手角色与空间关系，失败尝试也保留其意图而不暗示成功。

### 奖励标注

单一奖励模型按提示分三种模式：结果奖励对整段任务完成度打 1–5 分（可读出分布期望并归一到 [0,1] 作为连续奖励）；密集执行质量每 0.5 秒打 failure/suboptimal/normal 三档，回溯式标注（后续恢复不改善先前步），窗口 16 秒、步进 10 秒、丢弃每个非末窗的最后 4 秒以保证有后续视觉证据；量表奖励允许用户在测试时给出分步评分量表，模型以思考模式逐步打分并汇总。

### 训练策略

数据混合开源数据、授权专有数据与自采自标数据（人工标注员按详细指南提供密集描述与动作质量标签）。SFT 之后，分割模型进一步用 GRPO 做 RL：可验证奖励为 0.45·F@0.5 + 0.15·F@0.75 + 0.25·P@0.5 + 0.15·端点/续行标志准确率；描述模型用参考锚定的点质量奖励（类似 F1 的 r=2M/(R+M+F)）做 GRPO。发布版奖励模型只用 SFT。基础设施上 SFT 用 NeMo AutoModel，RL 为 PyTorch 自定义实现。

## 实验设置与数据

评测分四块。时间戳描述：公开的 WGO-Bench（25 条 HomER 人类第一视角 + 50 条 DROID 外视角 + 25 条 Galaxea 头部相机，共 100 条单视角视频，tIoU≥0.75 匹配），以及论文自建的 DenseCaptionBench（300 条完整 episode：100 人类 + 100 平行夹爪机器人 + 100 灵巧手机器人，保留全部相机视角，tIoU≥0.5，oracle 描述给部分分）。奖励标注：RoboRewardBench（2,831 条、人工 1–5 分，报 MAE）、RobometerBench（567 条 OOD 轨迹排序与进度）、自建 DenseRewardBench（40 条双手操作、4,861 个时间步、人工动作质量标签）与 RubricBench（40 条遥操作 episode、10 个任务、人工量表打分，报 L1 距离）。基线包括 GPT-6 Astra、GPT-5.6 Sol、Gemini 3.8 Flash、Claude Opus 5、Kimi K3、Qwen3.5-397B 等闭源/开源前沿模型，通用基线统一用"先分割后描述"的共同流水线与相同任务指令。效率对比在 50 条 DenseCaptionBench 子集（20 人 + 15 平夹 + 15 灵巧手）上按三种推理档评估，成本按 8 张 GB300、$10/GPU·小时估算。

## 结果、限制与结论

论文报告：WGO-Bench 上 Flora 分割 F1@0.75 达 50.3%（领先 Astra 的 46.0%），联合 F1 34.5% 仅次于 Astra 的 39.0%，金窗描述准确率 64.7%；对比同类流水线，比 Refiner 分割 F1 高 16.9 点、联合 F1 高 7.3 点。DenseCaptionBench Human100 上三项指标（分割 54.6%、描述质量 66.5%、联合 37.4%）全部第一，联合 F1 超 Astra 7.7 点；Robot200 三项均仅次于 Astra。奖励方面：RoboRewardBench MAE 40.0（Astra 55.4，专用模型 RoboReward 66.5，相对 Astra 降低 27.8%）；Robometer OOD Kendall 72.0 次于 Astra 的 82.3，ID/OOD VOC 98.9/99.6 与 Astra 持平或更高；DenseRewardBench 四项全优，macro F1 46.2，失败步召回 53.3%（无基线超过 11.7%，Astra 检不出失败）；RubricBench L1 6.5 优于十个通用模型中的九个（Astra 3.6 最好）。效率上，Flora 质量 57.1% @ $0.72/小时，Astra 最大推理档 53.7% @ $88.49/小时，约 125 倍成本差。

限制：论文自述 failure recall 的代价是把约 11% 的正常步也标成失败；WGO-Bench 金窗描述准确率仍低于 Astra 与 Gemini 3.8 Flash，收益主要来自时间定位；RubricBench 为内部基准；正文标注为技术报告（Blog Post 形式）而非同行评审论文。对具身数据基础设施方向而言，Flora 表明"专用数据引擎 + 开放权重"可以在质量-成本曲线上击败通用 API 标注，其分割/描述/奖励三件套与量表化奖励接口可直接用于组内数据引擎与评测管线的构建，模型已在 Hugging Face 开放。
