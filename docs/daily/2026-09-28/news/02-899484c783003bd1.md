## 事件概述

Anthropic 在 Opus 5.5 发布后数日内于官方文档更新了配套提示词指南，直接点名一类新型失效模式：无人值守 Agent 干着干着活就"提前下班"。据新智元 9 月 27 日报道，开发者在长任务中普遍遇到模型完成部分工作、汇报进度后即停止行动的现象；官方排查结论是 Opus 5.5 太爱汇报——长任务中它会主动同步进度，而 API 在汇报后返回 end_turn 信号，沿用旧逻辑的 Agent 程序把"这轮说完了"误判为"任务完成了"。

## 已确认事实与证据

官方指南（platform.claude.com 的 Opus 5.5 agentic 长任务提示工程页面）在开篇排查清单中列明该模式并给出处理建议；新智元报道引用了指南要点：纯文本的回合结束应视为一份进度汇报，绝不能当作任务完成凭据，Agent 程序需要据此改造终止判定逻辑。报道同时指出 Anthropic 在发布没几天就挂出了这份专门"打补丁"的指南。本文证据链包含新智元全文报道与官方指南 URL（官方页面为动态渲染，静态抓取仅得标题，细节以报道转述为准）。

## 影响与后续观察

这一官方确认对 Agent 基础设施开发者有直接工程价值：模型行为（主动汇报）与协议语义（end_turn）之间的错位是 harness 层 bug 的温床，任何"不再调用工具即视为完成"的实现都会踩坑。后续值得观察：主流 Agent 框架（Claude Code、Codex、开源 harness）是否会跟进调整终止判定；Opus 5.5 后续版本是否在模型侧缓解该倾向；以及官方指南是否进一步给出汇报-续作的结构化协议建议。
