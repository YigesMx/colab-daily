## 事件概述

Anthropic 开发者账号 @ClaudeDevs 官宣 Claude Code 的一项行为改进：当 5 小时用量上限在任务中途被触达时，不再"一刀切断"，而是短暂继续工作以到达一个合理的停点——官方称之为 Wrap-Up Allowance（收尾余量）。据新智元 9 月 27 日报道，这一改动解决了开发者长期抱怨的痛点：函数签名改了一半、调用处与测试尚未更新时进程被截断，留下一个需要人工逐处核对的半截仓库。

## 已确认事实与证据

Anthropic 官方帮助中心文章《Claude Code Wrap-Up Allowance》确认：触发用量上限时 Claude Code 会显示"Usage limit reached · wrapping up"，继续工作一小段以到达合理停点；该余量按计划 capped、并非无限，也不保证足以完成当前任务，耗尽后响应结束并回到正常限额直至重置。适用条件包括 Pro/Max 或带 Premium 席位的 Team 计划、Claude Code 2.1.277 或更高版本（终端、IDE 扩展或桌面 Code 标签页）、账号与组织满足最短存续期等。新智元报道补充了开发者社区的正面反响。本文证据链包含官方帮助中心页面全文与新智元报道。

## 影响与后续观察

对 Claude Code 用户这是直接的工作流改进：减少了限额触发的"半截改动"清理成本。值得观察的未知项：收尾余量的具体额度（官方未公布）、是否会扩展到 API/其他客户端、以及竞品（Codex、Gemini CLI 等）是否跟进类似"优雅触顶"机制。官方也明确该余量不能替代主动的保存与分段策略。
