**PyRUA-Dex: Learning Programmatic Policies for Dexterous Bimanual Manipulation with Coding Agents**

**一句话结论：** 北京大学 DAGroup 等机构提出的 PyRUA-Dex 让编码智能体（GPT-6 Astra 的 Codex CLI 会话）在仿真中通过"探索-精炼"两阶段为灵巧双手任务写出可冻结执行的 Python 程序策略，无需任何示教：在 Bench2Dex 上以 72.9 分刷新 SOTA（超过全部示教训练策略），在 DexJoCo 全随机化下成功率 81.0%，真机双 22 自由度手平台上 30 分钟即可从琴谱学会新钢琴曲。

## 研究问题与贡献

灵巧操作的现有学习范式高度依赖高质量示教：模仿学习、VLA 与世界-动作模型都以遥操作回合为训练数据，而多指手的高质量示教尤其稀缺——人类视频重定向不精确、遥操作无法给操作者力反馈、外骨骼采集难以规模化，且数据绑定在采集所用之手上。在 Bench2Dex（12 种臂-手本体的双臂任务基准）上，最强的示教训练策略成功率仅略过一半，且对布局扰动明显退化。

编码智能体提供了替代路径：把策略表示为可读、可测、可验证的程序而非网络权重。但此前机器人程序要么一次写成不做鲁棒性精炼，要么智能体必须留在测试回路中逐回合观测与决策（每回合消耗数百万 token）。本文提出的问题是：**编码智能体能否在开发期一次性学会一个灵巧任务，产出无需逐回合成本、可靠独立运行的程序？**

论文把这个任务分解为两个子问题并给出对应贡献：其一，**发现解**（抓取方式、双手次序、各阶段动作）是搜索问题，需要多智能体并行共享进展；其二，**让解鲁棒**——任务成功率是各阶段成功率的乘积（五个阶段各 80% 总成功率仅 33%），必须在大批随机布局上测每个阶段并改进最不可靠的瓶颈阶段。PyRUA-Dex 的贡献总结为：无需示教的智能体驱动灵巧操作框架、使用触觉反馈的两阶段程序化策略开发，以及覆盖 12 种灵巧手、仿真与真机的完整实验。作者来自北京大学、新加坡国立大学、NVIDIA、同济大学与芝加哥大学（Daquan Zhou 为通讯作者）。

## 方法与系统

### 策略形式与问题设定

每个任务求一个程序 πτ：输入与学习型策略在基准上得到的完全一致（标定 RGB 图像、臂手关节位置、指尖触觉图），输出关节位置目标；程序可调用正向运动学与分割模型（SAM 3），但不接收仿真器状态、物体位姿、阶段计数或成功信号，也不调用任何语言模型。任务按 K 个有序阶段评测，阶段成功率 rk 定义为"到达 k 阶段的布局数 / 到达 k−1 阶段的布局数"，总成功率按链式乘积分解——这一分解正是两阶段设计的依据：所有 rk 为正之前需要搜索（探索），之后对数收益最大来自最小 rk（精炼瓶颈）。学习是在开发预算（仿真布局数 B）下对程序搜索，测试布局从不用于开发，另有每任务 32 个验证布局决定程序是否被替换。

### 两阶段开发流程

**阶段一（探索）**：八个 Codex CLI 会话（GPT-6 Astra 最高推理强度、跨会话无记忆）并行各领一个训练布局与一个未解决阶段；智能体通过原语交互控制机器人，查询阶段计数，且每个布局可八次检查点/回退仿真器状态以反复重试单阶段。所有完成的尝试写入共享记忆（含到达阶段与代码），由专职智能体策展，一个智能体解决的阶段成为其他人的起点。探索结束时每个智能体写出程序，在八个新训练布局上无智能体评测；蒸馏智能体汇总所有评测记录写出任务库（每个阶段如何解决、成功率、代码），并选出最优程序（或按阶段拼装各智能体最常成功的阶段函数），只有在 32 个验证布局上不更差才替换。

**阶段二（精炼）**：单一智能体编辑程序。先在 32 个新训练布局上做逐阶段失败分析（每阶段进入/到达数、失败方式、剩余步数），定位瓶颈；随后逐阶段修复，用状态重置交互调试，再用"部分 rollout"（只执行到当前阶段）在数十个新布局上廉价评测（30 个布局的耗时约等于一个完整布局该阶段的耗时）；精炼期间回合步数预算翻倍，先可靠再快速。每 160 个训练布局评测一次，保留集上的最好版本才胜出；每任务至多 1,500 布局。

### 代码盒（codebox）原语

十二种手（6–22 个驱动关节，命名排列各异）由**同一套从机器人描述文件生成的原语库**控制：把每只手建模为手指+拇指、按功能分组关节（弯曲/卷曲/张开）、推导可握物体宽度，暴露"塑形手掌、按实测尺寸抓取、闭合直至握住、检查仍握住"等原语；接触从指尖触觉图与指令-实测关节位置的滞后读取；手臂原语移动手掌坐标系并提前报告不可达/碰撞；感知原语用 SAM 3 从标定相机定位物体。每个原语返回带原因的结果，程序可逐步检查重试。程序本身是固定结构：一个测量场景的 setup 函数加每阶段一个函数，失败的函数不中止回合，跑步器在剩余步数内重复调用。

### 真机迁移（real-to-sim-to-real）

真机平台为两台 Franka FR3 臂 + 两只 Sharpa Wave SE 手（各 22 关节）、上方 ZED-M 立体相机与每腕 Intel RealSense D405。仿真（MuJoCo）由平台标定构建：相机内外参、手眼变换、桌面、臂间变换与手安装；物体由照片/手机视频重建加少量实测尺寸；手的传动在真实控制器下做系统辨识——在拟合外的运动上仿真关节跟随真实关节误差 0.12–0.18 度（厂商模型为 0.80–3.1 度）；标定不确定的部分全部随机化。探索跑一次，精炼按轮进行：每轮后程序上真机执行（安全守卫拒绝任何逼近关节限位、桌面或另一臂数毫米内的动作），机器人暴露的差异写回仿真（实测桌面高度、拇指联动摆动、更软接触等）或任务规则，用户也可在机器人旁给出指令（如"捏刷子时离刷毛远一点"），下一轮在更新后的仿真中继续精炼同一程序。

## 实验设置与数据

仿真实验回答四个问题：Q1 程序是否超过示教训练策略；Q2 精炼贡献几何；Q3 冻结程序是否优于同模型在线操作；Q4 方法是否泛化到第二个基准。

- **Bench2Dex**：26 个双臂任务、12 种本体；按排行榜协议四通道各 50 回合评测（None 无扰动 / Inv. 不变性扰动 / Equi. 等变性扰动 / Full 两者皆有），报告成功率 SR、闩锁阶段完成率 LSCR、效率 Eff 与 Score=0.45SR+0.45LSCR+10Eff；
- **DexJoCo**：11 个 Allegro 手任务（MuJoCo），物体随机化（rand-obj）与再加相机/光照/纹理随机化（rand-full），三种子各 50 回合；
- **基线**：Bench2Dex 上全部报告四通道的排行榜条目（ACT、Diffusion Policy、π0.5、GR00T N1.5/N1.7（含触觉版）、Mora V0、MXI、Phoenix-MWA、GigaWorld-Policy-0.6、ME-Dex 1.5）与 DexJoCo 的五个训练策略；在线智能体基线为 SenseNova 的 GPT-6 Astra 智能体（同一模型、每回合在线控制）；
- **真机**：六个任务（双手各把立方体放篮、堆三立方塔、拿刷子写 Dex、三首钢琴曲（Ode to Joy、Twinkle Twinkle、Little Jumping Frog）），探索后按轮精炼，步频 30 Hz。

## 结果、限制与结论

### Bench2Dex：新 SOTA

PyRUA-Dex 得分 72.9，超过最强训练策略 ME-Dex 1.5 的 70.5；成功率 60.6%、阶段完成率 82.3% 均为全场最高（对比 ME-Dex 1.5 为 65.3% 与 76.3% 通道均值口径详见论文表 1）。四通道成功率极差仅 4.1 个百分点，且等变性通道（扰动改变正确动作）反而最好；每个训练策略都在扰动通道大幅退化（GR00T N1.7 从 39.4% 掉到 13.2%）——程序在每个回合测量场景并据此计算运动，而训练策略复现示教中见过的映射。在 26 个任务中的 15 个上超过最强训练策略，差距最大的是双臂钢琴旋律（99.5% 对 32.0%）；另外 11 个任务训练策略领先，其中三个任务的程序几乎从不成功，其共同点是开发期没有任何智能体解决某个阶段（锅放支架、倒完后放回瓶子、拼图超步数预算）。

### 精炼的贡献

精炼把成功率从 44.6% 提到 60.6%、得分从 59.1 到 72.9，26 任务中 20 个获益；最大增益来自文具分类（6.5% 到 49.0%）、烤盘准备（26.0% 到 68.0%）与探索从未完成的锤子任务（0% 到 37.0%）。失败分析显示探索后程序的 341 次验证失败中 68% 还剩至少 30% 步数预算、59% 是单一阶段函数失败后所有后续函数立即返回、仅 2% 用尽步数——重复调用失败阶段函数可以吃掉富余预算，而修瓶颈正对症。

### 冻结程序 vs 同模型在线

在基准步数预算下，冻结程序完成 61.5% 的 Full 通道回合，是在线智能体（25.6%，78 个全预算回合口径）的 2.4 倍；在线智能体要达到 61.5% 需要十倍步数预算、每回合 3,370 万 token。开发成本一次性支付：每任务中位数 4.27 亿 token 与 21.6 智能体小时（探索）加 2.14 亿 token 与 14.8 小时（精炼）；开发全部 26 个任务的 token 少于在线智能体跑基准 5,200 个测试回合（1 倍预算）的消耗，之后每个冻结程序回合零 token、按控制频率运行。

### DexJoCo 泛化

在无阶段定义、仅知回合成败的反馈条件下，方法原样迁移：rand-obj 成功率 88.5%、rand-full 81.0%，对最强训练策略 π0.5 的 54.1% 与 40.3%，且在两个设置的每个任务上都超过最佳训练策略；单一程序同时服务两个设置（全随机化下仅降 7.5 个百分点，各训练策略按各自设置训练仍降 9.7–30.4）。

### 真机

六个任务在验证布局上从探索后的 119/192 提升到 168/192；堆三立方从 6 提到 20 再到 30。仿真再标定偶尔打破程序（Ode to Joy 一度从 32 掉到 0，下一轮恢复到 31）。真机上冻结程序完成：双立方入篮（90 秒）、三立方塔（102 秒）、拉开并扶住盒盖、拿刷子写 Dex、双手弹 Night Cruise；从琴谱学一首新曲约 30 分钟。

### 限制

论文自述：编码智能体写运动很好、写持续接触很差——程序在几何、次序与时序决定的任务上最强，在需要连续控制力与滑动的任务上最弱（煎锅、手到手倾倒、拼图仍是训练策略领先，DexJoCo 装配任务仅 34.0%）；程序通过显式目标与阈值行动，仿真指尖传感器对接触的刻画粗糙（Bench2Dex 触觉图只在正对指垫的平面上响应），接触主要靠关节滞后推断；精炼只能强化已在部分布局上成立的阶段，从不成立的阶段仍是探索问题；每任务独立学习；真机上展示了冻结程序运行，但可靠性在标定仿真中测量而非重复硬件试验。未来方向包括把接触阶段交给学习控制器、更忠实的触觉仿真、跨任务库迁移与系统的硬件重复试验评测。
