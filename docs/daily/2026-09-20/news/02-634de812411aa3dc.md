## 事件概述

Anthropic 官宣重新设计的 Projects 功能正式落地 Claude Code：用户在一个项目对话中交代目标，Claude 作为协调器自行把工作拆分成多条云端线程并行执行，单日最多可新开 200 条线程，合上笔记本后任务继续运行。该功能以 Beta 形式先面向部分 Pro 与 Max 用户开放，随后一周扩大范围，最终覆盖全部 Claude 用户及 Team、Enterprise 版本。

## 已确认事实与证据

据新智元对 Anthropic 官方公告的报道，新版 Projects 采用两层架构。上层「项目对话」中 Claude 充当协调器，判断需求如何拆分、指派给新线程或复用已有线程，并负责审查与组装结果；下层「线程」是独立的 Claude Code 云端会话，各自持有上下文，在自己的 Git 分支与代码副本上工作。两条线程改动同一段代码时按普通 PR 合并冲突处理。线程还可以继续派生子智能体、循环与工作流。

官方示例显示，将目标设为「降低结账接口的 p75 延迟」后，Claude 会开线程分别分析接口性能、测试优化方案并提交 PR；跨 API、网页端、移动端三个仓库下线废弃接口时，每个仓库各开一条线程迁移调用方、跑测试、提 PR。PR 开出后线程会自行跟进 CI 失败与审查意见。项目引入共享记忆机制，发布日期、决策背景等工作习惯与项目资料只需交代一次，新线程自动继承。

资源与边界方面：项目默认使用 Opus 模型，与日常 Claude Code 会话共享额度，官方提示 Pro 用户额度会更早耗尽；线程数无硬性上限，唯一天花板是所有项目合计每日新开 200 条；额度耗尽时线程暂停等待恢复；当前线程全部运行在云端，无法访问本地文件、内网接口与 VPN 后服务。另据报道，Cursor 已于 9 月 10 日发布玩法相近的 Projects beta，两家在同期收敛到「协调者加子智能体并行」的同一方向。

## 影响与后续观察

该发布把多智能体编排从开发者手工调度推进为产品化默认能力，程序员的角色进一步从写代码转向定义目标与验收。共享记忆与自动 PR 跟进如果稳定，将显著降低长周期工程任务的切换成本。

待观察事项：200 线程上限与共享额度策略在实际项目中的消耗速度；多线程并行改动引发的合并冲突与审查质量；与 Cursor 同类功能的差异化竞争；以及企业版落地后对内部代码库的权限与审计方案。当前结论均来自官方公告与媒体首发报道，实际稳定性有待更多用户验证。
